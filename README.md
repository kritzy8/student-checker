## 1. ภาพรวมและความสามารถ

### นักเรียน
- ล็อกอินด้วยบัญชี Google ที่ลงทะเบียนไว้ ไม่ต้องพิมพ์ชื่อหรือรหัส
- สแกน QR จากหน้าจอหน้าห้อง แล้วระบบบันทึกให้ทันที
- ระบบตรวจ บัญชี ห้องเรียน รอบเช็กชื่อ และโทเค็น ก่อนบันทึก
- เช็กได้ครั้งเดียวต่อรอบ (สแกนซ้ำจะแจ้งว่า "เช็กชื่อไว้แล้ว")

### อาจารย์
- เลือกห้องและกำหนดเวลาเปิดรับ (1–30 นาที ค่าเริ่มต้น 5 นาที)
- แสดง QR ที่เปลี่ยนทุก 15 วินาที พร้อมแถบนับถอยหลัง
- เห็นจำนวนผู้เช็กแล้ว / ยังไม่เช็ก แบบเรียลไทม์ (อัปเดตทุก 3 วินาที)
- **ติ๊กให้นักเรียน** ที่ไม่มีมือถือหรือเน็ตมีปัญหา (บันทึกวิธีเป็น `manual`)
- **ยกเลิกการเช็ก** รายบุคคล กรณีตรวจพบการเช็กแทนกัน
- แจ้งเตือน ⚠ เมื่อพบอุปกรณ์เดียวกันเช็กหลายบัญชี
- ปิดรับก่อนเวลาได้ และเริ่มรอบใหม่ต่อได้ทันที

### ผู้ดูแลระบบ
- **แดชบอร์ด** ตารางสอนวันนี้ (ไฮไลต์คาบปัจจุบัน) สรุปการเข้าเรียน 7 วันล่าสุด แยกตามห้อง และรายชื่อนักเรียนที่ควรติดตาม
- **ตารางสอน** จันทร์–ศุกร์ 8 คาบ คลิกช่องเพื่อเพิ่ม/แก้ไข/ลบ รองรับการสอนต่อเนื่องหลายคาบ (ช่องที่ติดกันและข้อมูลเหมือนกันจะรวมเป็นช่องเดียว) มีมุมมองรายวันบนมือถือ
- **รายชื่อนักเรียน** เพิ่ม/แก้ไข/ลบ ค้นหาด้วยเลขที่ ชื่อ อีเมล หรือหมายเหตุ และเพิ่มห้องใหม่ได้ขณะเพิ่มนักเรียน
- **หมายเหตุนักเรียน** บันทึกข้อความส่วนตัว (เห็นเฉพาะแอดมิน สูงสุด 500 ตัวอักษร) แสดงไอคอน 📝 ในรายการ
- **รายงานผล** กรองตามห้องและช่วงวันที่ (วันนี้ / 7 วัน / 30 วัน / ทั้งหมด) ดูภาพรวม แนวโน้มรายคาบ/รายวัน และสมุดเช็กชื่อรายบุคคล
- **ปรับสถานะ** มาเรียน / มาสาย / ลา / ขาด พร้อมหมายเหตุ คลิกที่ช่องของนักเรียนแต่ละคาบ หรือเปิดทั้งคาบเพื่อปรับหลายคน และคืนค่ากลับตามระบบได้
- **ดาวน์โหลด Excel (.xlsx)** พร้อมสูตรสรุป การจัดรูปแบบ และตั้งค่าพิมพ์แนวนอน
- **ยกเลิกรอบ (void)** กรณีเปิดผิดหรือทดสอบ

## 2. สถาปัตยกรรม

ใช้ Apps Script **2 โปรเจ็กต์แยกกัน**

| โปรเจ็กต์ | หน้าที่ | ไฟล์ |
| --- | --- | --- |
| **Main** | แสดงหน้าเว็บ ตรวจสิทธิ์ และอ่าน/เขียน Google Sheets | `Code.gs`, `Auth.gs`, `Home.html`, `Teacher.html`, `Student.html`, `Admin.html`, `appsscript.json` |
| **Bridge** | อ่านอีเมล Google ของผู้เข้าชม ออกตั๋ว (ticket) ลงลายเซ็น แล้วส่งต่อไป Main | `Code.gs` (ของ Bridge), `appsscript.json` (ของ Bridge) |

> `Code.gs` ของ Main และ Bridge เป็นคนละไฟล์ที่ชื่อซ้ำกัน ต้องวางคนละโปรเจ็กต์ อย่าสลับกัน

**เหตุผลที่แยก:** การอ่านอีเมลผู้ใช้ต้อง Deploy แบบ *User accessing the web app* ส่วนการเข้าถึงชีตของเจ้าของระบบต้อง Deploy แบบ *Me* จึงแยกเป็นสองแอป

```text
ผู้ใช้ ──► Bridge (อ่านอีเมล + สร้างตั๋ว HMAC-SHA256)
              │
              ▼
          Main (ตรวจตั๋ว + ตรวจสิทธิ์)
              ├─ นักเรียน : หน้าเช็กชื่อ
              ├─ อาจารย์  : เปิดรอบ + แสดง QR
              └─ แอดมิน   : แดชบอร์ด / รายงาน / จัดการข้อมูล
              │
              ▼
          Google Sheets
```

### ตั๋วยืนยันตัวตน
- รูปแบบ `base64(email|หมดอายุ).ลายเซ็น` ลงลายเซ็นด้วย `AUTH_SECRET`
- หน้าเช็กชื่อนักเรียน (`p=c`) อายุ **10 นาที** หน้าอื่น **8 ชั่วโมง**
- ตั๋วอยู่ใน URL (`auth=`) ถือเป็นข้อมูลอ่อนไหว อย่าส่งต่อหรือโพสต์สาธารณะ
- เปิด Main โดยไม่มีตั๋วหรือตั๋วไม่ถูกต้อง ระบบจะส่งกลับไปยืนยันที่ Bridge ให้เอง
- ทุกการเรียกจากหน้าเว็บผ่านฟังก์ชัน `api()` ใน `Auth.gs` ซึ่งตรวจตั๋วและใช้ whitelist ของฟังก์ชัน

### พารามิเตอร์หน้าเว็บ (`?p=`)

| ค่า | หน้า |
| --- | --- |
| (ไม่ระบุ) | หน้าแรก เมนูตามสิทธิ์ (เช็กชื่อนักเรียน / สรุปผล) |
| `t` | อาจารย์: เปิดรอบและแสดง QR |
| `admin` | ผู้ดูแลระบบ |
| `c` | นักเรียน: เช็กชื่อ (ใช้ `s` = รหัสรอบ, `t` = โทเค็น) |
| `ok` | ให้นักเรียนเปิดครั้งแรกเพื่อกดอนุญาตบัญชีล่วงหน้า |

**แจกลิงก์ของ Bridge เป็นจุดเริ่มต้นเสมอ**

## 3. ติดตั้งและตั้งค่า

### สิ่งที่ต้องเตรียม
1. บัญชี Google ของเจ้าของระบบ (เป็นเจ้าของทั้ง Sheets และ Apps Script ทั้งสองโปรเจ็กต์)
2. Google Sheets ว่าง 1 ไฟล์
3. อีเมล Google ของนักเรียน อาจารย์ และผู้ดูแล
4. แนะนำ Chrome เวอร์ชันล่าสุด

### A. สร้าง Main
1. สร้าง Google Sheets ใหม่ แล้วเปิด **ส่วนขยาย → Apps Script**
2. วาง `Code.gs` และสร้างไฟล์ `Auth` (สคริปต์) วาง `Auth.gs`
3. สร้างไฟล์ HTML ชื่อ `Home`, `Teacher`, `Student`, `Admin` แล้ววางโค้ดตามชื่อ
4. ตั้งค่า `appsscript.json` ของ Main (เปิดดูได้ที่ **Project Settings → Show "appsscript.json"**) ให้ `webapp.executeAs` เป็น `USER_DEPLOYING` และตั้งค่า `timeZone` เป็น `Asia/Bangkok`
5. รันฟังก์ชัน `setup` (กดอนุญาตสิทธิ์) เพื่อสร้างชีตทั้งหมด บันทึก `SS_ID` และเพิ่มบัญชีของคุณเป็นอาจารย์/แอดมินเริ่มต้น
6. รันฟังก์ชัน `createAuthSecret` แล้วคัดลอกค่า `AUTH_SECRET` จาก Execution log
7. **Deploy → New deployment → Web app** โดย Execute as = **Me** เลือก Who has access ให้ผู้ใช้ทุกกลุ่มเข้าถึงได้ (เช่น Anyone with Google account) แล้วคัดลอก URL `/exec` เป็น `MAIN_URL`

### B. สร้าง Bridge
1. สร้างโปรเจ็กต์ Apps Script ใหม่ แยกจาก Main
2. วางโค้ด Bridge ลงใน `Code.gs`
3. ตั้งค่า `appsscript.json` ของ Bridge ให้มี
   - `"oauthScopes": ["https://www.googleapis.com/auth/userinfo.email"]`
   - `"webapp": { "executeAs": "USER_ACCESSING", "access": "ANYONE" }`
4. **Project Settings → Script Properties** เพิ่ม `AUTH_SECRET` = ค่าจากข้อ A.6 (ต้องตรงกันทุกตัวอักษร)
5. Deploy เป็น Web app แบบ **User accessing the web app** แล้วคัดลอก URL `/exec` เป็น `BRIDGE_URL`

### C. เชื่อมสองโปรเจ็กต์
| โปรเจ็กต์ | ไฟล์ | ตัวแปร |
| --- | --- | --- |
| Main | `Auth.gs` | `BRIDGE_URL` = URL ของ Bridge |
| Bridge | `Code.gs` | `MAIN_URL` = URL ของ Main |

จากนั้น Deploy ทั้งสองโปรเจ็กต์เป็น **New version** (Deploy → Manage deployments → Edit → New version) การบันทึกไฟล์อย่างเดียวไม่ทำให้เว็บแอปที่ Deploy อยู่เปลี่ยนตาม

### D. เตรียมผู้ใช้และทดสอบ
1. ใส่รายชื่อใน `Students`, `Teachers`, `Admins` (ดูหัวคอลัมน์ในหัวข้อถัดไป หรือใช้หน้า Admin เพิ่มนักเรียน)
2. รัน `clearCache` เมื่อแก้ `Teachers`/`Admins`/`Students` ในชีตโดยตรง
3. ให้นักเรียนเปิด `BRIDGE_URL?p=ok` หนึ่งครั้ง เพื่อกดอนุญาตบัญชี
4. ทดสอบเป็นอาจารย์ (เปิดรอบ ดู QR) นักเรียน (สแกน) และแอดมิน (รายงาน, Excel)
5. ทดสอบกับจำนวนผู้ใช้ใกล้เคียงการใช้งานจริงก่อนเริ่มใช้

## 4. โครงสร้าง Google Sheets

`setup()` สร้างชีตและหัวคอลัมน์ให้ (ชีตเดิมจะเติมเฉพาะหัวที่ขาด ไม่แตะข้อมูล)

| ชีต | คอลัมน์ | หน้าที่ |
| --- | --- | --- |
| `Students` | `email, studentId, name, class` | รายชื่อนักเรียน (ทุกคอลัมน์เป็นข้อความล้วน) |
| `Teachers` | `email, name, fullName` | อีเมลที่มีสิทธิ์อาจารย์ |
| `Admins` | `email, name, fullName` | อีเมลที่มีสิทธิ์แอดมิน |
| `Sessions` | `sessionId, class, teacher, start, end, secret, status` | รอบเช็กชื่อ (`status` = `open` / `closed` / `void`) คอลัมน์ `secret` ถูกซ่อนไว้ |
| `Attendance` | `timestamp, sessionId, class, email, studentId, name, deviceId, method, flag` | บันทึกการเช็ก (`method` = `qr` / `manual`, `flag` = `DEVICE_SHARED` เมื่อพบอุปกรณ์ซ้ำ) |
| `Adjustments` | `sessionId, email, status, note, by, updatedAt` | การปรับสถานะโดยแอดมิน |
| `Schedule` | `entryId, teacher, day, period, class, subject, room, updatedAt` | ตารางสอน (`day` 1–5 = จันทร์–ศุกร์) |
| `StudentNotes` | `email, note, updatedAt` | หมายเหตุนักเรียน (สร้างอัตโนมัติเมื่อใช้ครั้งแรก) |

`fullName` ในชีต `Teachers`/`Admins` ใช้แสดงในคำทักทายหน้าแรกและแดชบอร์ด

**ข้อควรระวัง:** `Sessions` เก็บ secret ของ QR และ Script Properties เก็บ `AUTH_SECRET` อย่าแชร์ Spreadsheet หรือสิทธิ์แก้ Apps Script ให้นักเรียน

## 5. สิทธิ์การใช้งาน

| กลุ่ม | แหล่งสิทธิ์ | ทำอะไรได้ |
| --- | --- | --- |
| นักเรียน | `Students` | เช็กชื่อในรอบของห้องตัวเอง |
| อาจารย์ | `Teachers` | เปิด/ปิดรอบ ดู QR ติ๊กให้ ยกเลิกการเช็ก |
| ผู้ดูแลระบบ | `Admins` | แดชบอร์ด ตารางสอน รายชื่อ รายงาน ปรับสถานะ void |

- หน้าแรกจะแสดงเมนูที่ไม่มีสิทธิ์เป็นสีจางพร้อมป้าย "เฉพาะอาจารย์ / เฉพาะผู้ดูแลระบบ"
- การซ่อนเมนูไม่ใช่มาตรการความปลอดภัย ทุกฟังก์ชันฝั่งเซิร์ฟเวอร์ตรวจสิทธิ์ซ้ำ (`requireTeacher_`, `requireAdmin_`)
- แอดมินที่ต้องการเปิดรอบเช็กชื่อด้วย ต้องอยู่ในชีต `Teachers` ด้วย
- แอดมินที่เป็นอาจารย์สามารถกด "กลับหน้าแอดมิน" จากหน้าเช็กชื่อ และกด "เช็กชื่อ" จากเมนูข้างของแอดมินได้

## 6. วิธีใช้งาน

### อาจารย์
1. เปิดลิงก์ Bridge → เลือก **เช็กชื่อนักเรียน**
2. เลือกห้องและเวลา → **เริ่มเช็กชื่อ** (แสดง QR บนโปรเจกเตอร์)
3. นักเรียนสแกน ระบบอัปเดตรายชื่อให้อัตโนมัติ
4. ใช้ปุ่ม **ติ๊กให้** / **ยกเลิก** เมื่อจำเป็น และ **ปิดรับเช็กชื่อ** เมื่อเสร็จ

### นักเรียน
1. ล็อกอินบัญชี Google ที่ลงทะเบียนไว้ (ใช้ Chrome โปรไฟล์ที่ถูกบัญชี)
2. สแกน QR ด้วยกล้องโทรศัพท์
3. รอผล ✓ เช็กชื่อสำเร็จ หาก QR หมดอายุให้สแกนใหม่จากหน้าจอปัจจุบัน

### ผู้ดูแลระบบ

**ตารางสอน**
- ผูกกับอีเมลของแอดมินที่บันทึก ใช้แสดงในแดชบอร์ดและใช้จับคู่ชื่อวิชา/คาบ/สถานที่ในรายงาน
- การจับคู่ใช้ อีเมลอาจารย์ที่เปิดรอบ + วัน + คาบ (รอบที่เปิดก่อนคาบไม่เกิน 15 นาทีนับเป็นคาบนั้น) จึงควรให้เจ้าของตารางสอนเป็นคนเปิดรอบเอง
- ตารางสอนไม่ได้เปิดรอบเช็กชื่ออัตโนมัติ

**รายชื่อนักเรียน**
- อีเมลต้องไม่ซ้ำทั้งระบบ เลขที่ต้องไม่ซ้ำภายในห้องเดียวกัน
- เลขที่เก็บเป็นข้อความ (รักษาเลขศูนย์นำหน้า) และเรียงเชิงตัวเลข (2 ก่อน 10)
- **แก้อีเมลผ่านหน้า Admin** ระบบจะย้ายประวัติใน `Attendance` และ `Adjustments` ตามให้ แต่ถ้าแก้ในชีตโดยตรงจะไม่ย้าย ทำให้ประวัติหายและถูกนับเป็นขาด
- **ลบนักเรียน** จะลบแถวใน `Students` และหมายเหตุ แต่ประวัติใน `Attendance` และ `Adjustments` ยังอยู่

**รายงานผล**
- เปิดครั้งแรกโหลดย้อนหลัง 30 วันเป็นค่าเริ่มต้น
- แท็บ *แยกรายบุคคล* แสดงสมุดเช็กชื่อ จัดกลุ่มตามเดือน → วัน → คาบ ตรึงคอลัมน์ซ้าย/ขวา และเรียงตามเลขที่ / % เข้าเรียน / จำนวนขาด
- แท็บ *แยกแต่ละวัน/คาบ* มีโหมดรายคาบและรายวัน คลิกแถวเพื่อดูและแก้ทั้งคาบ
- คลิกชื่อนักเรียนเพื่อดูประวัติรายบุคคล คลิกช่องสถานะเพื่อแก้เฉพาะคาบนั้น (แสดงวิชา คาบ เวลาที่เช็กจริง และวิธีเช็ก)

**ปรับสถานะและยกเลิกรอบ**
- การปรับบันทึกใน `Adjustments` ปุ่ม *คืนค่า* จะลบการปรับและกลับไปใช้ผลจากระบบ
- *ตั้งค่าให้ไม่นับคาบนี้* (void) ไม่ลบข้อมูล แต่ตัดรอบออกจากรายงานและแดชบอร์ด และกู้คืนจากหน้าเว็บไม่ได้ (ต้องแก้คอลัมน์ `status` ในชีต `Sessions` เอง)

**ดาวน์โหลด Excel**
- สร้างฝั่งเบราว์เซอร์ด้วย ExcelJS 4.4.0 ที่โหลดจาก CDN (jsdelivr) จึงต้องมีอินเทอร์เน็ต
- ไฟล์ตรงกับตารางรายบุคคลที่เห็นบนจอ รวมลำดับการเรียงที่เลือก มีสูตร `COUNTA`/`COUNTIF` สรุปผล ตรึงหัวตาราง และเน้นสีแดงเมื่อ % ต่ำกว่าเกณฑ์

## 7. หลักการคำนวณสถานะ

| รหัส | ความหมาย | สัญลักษณ์ |
| --- | --- | --- |
| `p` | มาเรียน | `/` |
| `l` | มาสาย | `ส` |
| `v` | ลา | `ล` |
| `a` | ขาด | `ข` |

ลำดับการตัดสิน:
1. มีการปรับโดยแอดมิน (`Adjustments`) → ใช้สถานะนั้น
2. ไม่มีการปรับ แต่มีบันทึกใน `Attendance` (สแกนหรืออาจารย์ติ๊ก) → **มาเรียน**
3. ไม่มีทั้งสอง → **ขาด**

หมายเหตุ:
- ระบบอัตโนมัติแยกได้แค่ มา/ขาด ส่วน **สาย และ ลา ต้องให้แอดมินปรับเอง**
- อัตราเข้าเรียน = (มา + สาย) ÷ ทั้งหมด การลาไม่นับเป็นเข้าเรียน
- ต่ำกว่า **80%** แสดงสีแดง
- รายงานนับเฉพาะรอบที่ปิดแล้วหรือหมดเวลาแล้ว ไม่รวมรอบที่ยังเปิดอยู่และรอบ `void`
- รายชื่อที่ใช้คำนวณคือนักเรียนใน `Students` ปัจจุบันของห้องนั้น นักเรียนที่ถูกลบจะไม่ปรากฏในรายงาน และนักเรียนที่เพิ่มภายหลังจะถูกนับเป็นขาดในรอบเก่าด้วย
- แดชบอร์ด "ควรติดตาม" แสดงนักเรียนที่มีข้อมูลอย่างน้อย 3 คาบ และอัตราต่ำกว่าเกณฑ์ สูงสุด 8 คน

## 11. การสำรองและดูแลข้อมูล

1. สำรอง Spreadsheet ด้วย **File → Make a copy** ก่อนแก้ข้อมูลจำนวนมากหรือปรับโครงสร้าง
2. จำกัดสิทธิ์เข้าถึง Spreadsheet และ Apps Script เฉพาะผู้ดูแล
3. อย่าลบ/เปลี่ยนชื่อหัวคอลัมน์ในชีตระบบ เพราะโค้ดอ่านตามตำแหน่งและชื่อ
4. ใช้ `Attendance`, `Sessions`, `Adjustments` ตรวจสอบประวัติย้อนหลัง
5. เก็บ `AUTH_SECRET` ใน Script Properties เท่านั้น ห้ามใส่ในโค้ด README หรือ repository สาธารณะ
6. หากสงสัยว่า `AUTH_SECRET` รั่ว ให้รัน `createAuthSecret` ใน Main แล้วนำค่าใหม่ไปแทนที่ใน Script Properties ของ Bridge จากนั้น Deploy ใหม่ทั้งสองโปรเจ็กต์
7. การแก้ข้อมูลชีตโดยตรงให้รัน `clearCache` เพื่อล้างแคช `students`, `teachers`, `admins` (แคชรอบและบันทึกเช็กชื่อหมดอายุเอง)

## 12. ข้อจำกัด

- **กันการเช็กแทนได้ไม่ 100%** หากนักเรียนที่อยู่ในห้องล็อกอินบัญชีเพื่อนบนเครื่องตนเองแล้วสแกน ระบบอาจตรวจไม่พบ แฟลกอุปกรณ์ซ้ำเป็นเพียงสัญญาณ ไม่ใช่หลักฐานยืนยันตัวบุคคล และหากล้างข้อมูลเบราว์เซอร์ `deviceId` จะเปลี่ยน
- **โควตา Apps Script** คำขอทั้งหมดใช้โควตาของเจ้าของระบบ หากสแกนพร้อมกันจำนวนมากอาจช้าหรือต้องสแกนใหม่ ควรทดสอบก่อนใช้จริง
- **ตั๋วนักเรียนอายุ 10 นาที** เปิดหน้าค้างนานต้องสแกนใหม่
- **ล็อกอินหลายบัญชี Google** ในเบราว์เซอร์เดียวอาจเลือกผิดบัญชี
- **ไม่แยกมาสายอัตโนมัติ** การสแกนทุกกรณีนับเป็นมาเรียน
- **ตารางสอนเป็นข้อมูลประกอบ** ไม่ได้ควบคุมการเปิดรอบ
- **Excel ต้องใช้อินเทอร์เน็ต** เพราะโหลด ExcelJS จาก CDN
- **ฟอนต์ Noto Sans Thai และไลบรารี QR** โหลดจาก CDN (Google Fonts, cdnjs) หน้าอาจารย์ต้องเข้าถึง cdnjs ได้เพื่อสร้าง QR
- **ข้อมูลส่วนบุคคล** ระบบเก็บอีเมล เวลาเช็กชื่อ และรหัสอุปกรณ์ ควรแจ้งผู้เรียน/ผู้ปกครองและปฏิบัติตามนโยบายคุ้มครองข้อมูลของสถานศึกษา

## 14. หมายเหตุสำหรับผู้พัฒนา

- ห้ามเปิดเผย `AUTH_SECRET` หรือ URL ที่มี `auth=`
- เพิ่ม/เปลี่ยนฟังก์ชันที่หน้าเว็บเรียก ต้องเพิ่มใน whitelist `FN` ของ `api()` (`Auth.gs`) และเรียก `requireTeacher_()`/`requireAdmin_()` ภายในฟังก์ชันนั้น
- ก่อนเปลี่ยนชื่อชีตหรือหัวคอลัมน์ ตรวจ `SHEETS` และ `HEADERS` ใน `Code.gs` ทุกจุดที่อ้างถึง
- ทดสอบทั้งสามบทบาท (นักเรียน อาจารย์ แอดมิน) ก่อน Deploy ใช้งานจริง
- ข้อสังเกตจากโค้ดปัจจุบัน (ไม่กระทบการทำงานหลัก):
  - `downloadExcelReport` ใน `Code.gs` (สร้างไฟล์ `.xls` ฝั่งเซิร์ฟเวอร์) ยังอยู่ใน whitelist แต่หน้า Admin ไม่ได้เรียกใช้แล้ว ใช้ ExcelJS ฝั่งเบราว์เซอร์แทน
  - สคริปต์ท้ายไฟล์ `Home.html` เรียก `getUserProfile` ซึ่งไม่อยู่ใน whitelist และอ้างถึง element `welcomeMsg` ที่ไม่มีในหน้า จึงไม่ทำงาน (คำทักทายจริงมาจาก template ฝั่งเซิร์ฟเวอร์) ลบส่วนนี้ได้
  - `Code.gs` มีคอมเมนต์ว่าอายุ QR 15–30 วินาที แต่ด้วย `GRACE_SLOTS = 2` อายุจริงอยู่ที่ประมาณ 30–45 วินาที
