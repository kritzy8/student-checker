# ระบบเช็กชื่อด้วย QR หมุนเวียน

เว็บแอปเช็กชื่อนักเรียนด้วย QR Code ที่เปลี่ยนทุก 15 วินาที พร้อมระบบหลังบ้านสำหรับผู้ดูแลระบบ (แดชบอร์ด ตารางสอน จัดการรายชื่อนักเรียน รายงานผล และส่งออก Excel) สร้างบน Google Apps Script + Google Sheets

ระบบแบ่งเป็น **2 โปรเจ็กต์ Apps Script** ที่ทำงานร่วมกัน:

| โปรเจ็กต์          | หน้าที่                                                                | ไฟล์                                                                                               |
| ------------------ | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| **แอปหลัก (Main)** | หน้าเว็บทั้งหมด ฐานข้อมูล (Google Sheets) และตรรกะเช็กชื่อ/รายงาน      | `Code.gs`, `Auth.gs`, `Home.html`, `Teacher.html`, `Student.html`, `Admin.html`, `appsscript.json` |
| **Bridge**         | อ่านอีเมล Google ของผู้ใช้ แล้วออก "ตั๋ว" ที่ลงลายเซ็นส่งต่อให้แอปหลัก | `Code.gs`, `appsscript.json`                                                                       |

## สถาปัตยกรรมและการยืนยันตัวตน

เหตุผลที่แยก Bridge ออกมา: แอปหลักทำงานในนามเจ้าของสคริปต์ (เข้าถึงชีตได้) จึงอ่านอีเมลของผู้เข้าชมเองไม่ได้ ส่วน Bridge ทำงานในนามผู้เข้าชม (**Execute as: User accessing the web app**) จึงอ่านอีเมลได้ แล้วส่งต่อให้แอปหลักอย่างปลอดภัย ผลที่ได้คือ **ใช้ได้กับบัญชี @gmail.com และโดเมนต่างกัน** ไม่จำเป็นต้องอยู่ใน Google Workspace เดียวกัน

```
ผู้ใช้ ──► Bridge (อ่านอีเมล + เซ็นตั๋ว HMAC) ──► แอปหลัก (ตรวจตั๋ว → แสดงหน้า / เรียก API)
```

**ตั๋ว (auth ticket)** มีรูปแบบ `base64(อีเมล|เวลาหมดอายุ).ลายเซ็น HMAC-SHA256` ลงลายเซ็นด้วยรหัสลับ `AUTH_SECRET` ที่ **ต้องเหมือนกันทั้ง 2 โปรเจ็กต์**

| ปลายทาง                                  | อายุตั๋ว  |
| ---------------------------------------- | --------- |
| หน้าเช็กชื่อของนักเรียน (`?p=c`)         | 10 นาที   |
| หน้าอื่นทั้งหมด (อาจารย์/แอดมิน/หน้าแรก) | 8 ชั่วโมง |

**พารามิเตอร์ `?p=` ของแต่ละหน้า**

| ค่า       | หน้า                                                                          | เรียกผ่าน          |
| --------- | ----------------------------------------------------------------------------- | ------------------ |
| (ไม่ระบุ) | หน้าแรก เมนูเลือกตามสิทธิ์                                                    | Bridge หรือแอปหลัก |
| `t`       | หน้าเช็กชื่อของอาจารย์ (ฉายโปรเจกเตอร์)                                       | Bridge             |
| `admin`   | ระบบหลังบ้านผู้ดูแลระบบ                                                       | Bridge             |
| `c`       | หน้าเช็กชื่อของนักเรียน (มาจากการสแกน QR พร้อม `s`=รหัสรอบ, `t`=โทเค็น)       | Bridge             |
| `ok`      | หน้ายืนยันว่าเชื่อมบัญชีสำเร็จ (ให้นักเรียนเปิดครั้งแรกเพื่อกดอนุญาตล่วงหน้า) | Bridge             |

> ลิงก์ที่ใช้งานจริงควรชี้ไปที่ **URL ของ Bridge** เสมอ (เช่น `BRIDGE_URL?p=t`) ถ้าเปิดแอปหลักตรง ๆ โดยไม่มีตั๋ว ระบบจะเด้งไป Bridge เพื่อยืนยันตัวตนให้เอง

**การเรียก API จากหน้าเว็บ** ทุกคำขอผ่านฟังก์ชันเดียว `api(auth, fn, args)` ใน `Auth.gs` ซึ่งตรวจตั๋วก่อน และอนุญาตเฉพาะฟังก์ชันที่อยู่ใน whitelist แต่ละฟังก์ชันตรวจสิทธิ์ซ้ำอีกชั้น (`requireTeacher_` / `requireAdmin_`) ไม่ได้อาศัยแค่การซ่อนปุ่มหน้าเว็บ

## รายละเอียดโปรเจ็กต์ Bridge

Bridge เป็นโปรเจ็กต์ Apps Script ขนาดเล็ก (ไฟล์ `Code.gs` + `appsscript.json`) ทำหน้าที่เดียวคือ **ยืนยันตัวตน**: อ่านอีเมล Google ของผู้เข้าชม ออกตั๋วลงลายเซ็น แล้วส่งต่อไปแอปหลักพร้อมพารามิเตอร์เดิมทุกตัว Bridge **ไม่เก็บข้อมูล ไม่ตรวจสิทธิ์ครู/แอดมิน ไม่เข้าถึง Google Sheets** การตัดสินว่าใครเป็นนักเรียน/อาจารย์/แอดมินเป็นหน้าที่ของแอปหลักทั้งหมด

### ขั้นตอนการทำงานของ `doGet`

1. รับคำขอ (เช่น `BRIDGE_URL?p=c&s=<รหัสรอบ>&t=<โทเค็น QR>`) แล้วอ่านอีเมลจาก `Session.getActiveUser().getEmail()` (แปลงเป็นตัวพิมพ์เล็กและตัดช่องว่าง) ซึ่งทำได้เพราะ Bridge ทำงานในนามผู้เข้าชม
2. ถ้าอ่านอีเมลไม่ได้ แสดงข้อความ "อ่านอีเมลไม่ได้ กรุณาล็อกอินบัญชี Google แล้วลองใหม่" และหยุด
3. กำหนดอายุตั๋วตามหน้าปลายทาง: `p=c` (เช็กชื่อนักเรียน) **10 นาที** หน้าอื่นทั้งหมด **8 ชั่วโมง**
4. สร้าง payload `อีเมล|เวลาหมดอายุ(มิลลิวินาที)` แล้วออกตั๋ว `base64url(payload).HMAC-SHA256(payload)` ด้วย `AUTH_SECRET`
5. รวมพารามิเตอร์เดิมทั้งหมดกับ `auth=<ตั๋ว>` (ถ้าผู้ใช้ส่ง `auth` มาเองจะถูกเขียนทับ ค่าว่างถูกตัดทิ้ง) แล้วส่งต่อไป `MAIN_URL`

### หน้าเปลี่ยนเส้นทาง

Bridge ไม่ได้ redirect ด้วย HTTP โดยตรง (Apps Script ทำไม่ได้) แต่แสดงหน้า "ยืนยันตัวตนแล้ว: <อีเมล>" พร้อมสคริปต์ที่เปลี่ยนหน้าบนสุด (`window.top.location`) อัตโนมัติ และมีปุ่ม **"ดำเนินการต่อ"** สำรองไว้ เผื่อเบราว์เซอร์บล็อกการเปลี่ยนหน้าอัตโนมัติ

### ฟังก์ชันในโปรเจ็กต์

| ฟังก์ชัน                               | หน้าที่                                                                                                               |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `doGet(e)`                             | ทางเข้าเดียว อ่านอีเมล ออกตั๋ว ส่งต่อไปแอปหลัก                                                                        |
| `authSign_(s)`                         | เซ็น HMAC-SHA256 ด้วย `AUTH_SECRET` ใน Script Properties (ไม่มีรหัสจะโยน error "Bridge ยังไม่ได้ตั้งค่า AUTH_SECRET") |
| `buildQuery_(obj)`                     | สร้าง query string พร้อม URL-encode และข้ามค่าว่าง                                                                    |
| `escHtml_(s)`                          | escape อีเมลก่อนแสดงบนหน้าเว็บ กัน HTML แทรก                                                                          |
| `goTopPage_(url, message, buttonText)` | สร้างหน้าเปลี่ยนเส้นทางพร้อมปุ่มสำรอง                                                                                 |

### การตั้งค่าที่ต้องมี

| รายการ                            | ค่า                                                                                                               |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `MAIN_URL` (ค่าคงที่ใน `Code.gs`) | URL `/exec` ของแอปหลัก                                                                                            |
| Script Property `AUTH_SECRET`     | ต้องเหมือนค่าในแอปหลักทุกตัวอักษร                                                                                 |
| `appsscript.json`                 | `timeZone: Asia/Bangkok`, `runtimeVersion: V8`, `oauthScopes: ["https://www.googleapis.com/auth/userinfo.email"]` |
| Deploy as Web app                 | Execute as: **User accessing the web app** / Who has access: **Anyone** (หรือ Anyone with Google account)         |

ผู้ใช้ครั้งแรกจะเห็นหน้าขออนุญาตให้ Bridge อ่านอีเมล จึงให้นักเรียนเปิด `BRIDGE_URL?p=ok` ล่วงหน้า 1 ครั้ง

### หมายเหตุด้านความปลอดภัยของ Bridge

- ตั๋วอยู่ใน URL (query string) และ payload เป็น base64 **ไม่ได้เข้ารหัส** ใครเห็นตั๋วอ่านอีเมลเจ้าของได้ และใช้ตั๋วนั้นเข้าแอปหลักในนามเจ้าของได้จนกว่าจะหมดอายุ (ตั๋วนักเรียนอายุสั้น 10 นาที ส่วนตั๋วอาจารย์/แอดมิน 8 ชั่วโมง) จึง **อย่าแชร์ลิงก์ที่มี `auth=` ให้ใคร** และไม่ควรแคปหน้าจอแถบที่อยู่ลิงก์
- ผู้ใช้ปลอมตั๋วเองไม่ได้ เพราะไม่รู้ `AUTH_SECRET` และแอปหลักตรวจลายเซ็นและวันหมดอายุทุกคำขอ
- ถ้าสงสัยว่า `AUTH_SECRET` รั่ว ให้รัน `createAuthSecret` ในแอปหลักเพื่อสร้างรหัสใหม่ แล้วอัปเดตใน Script Properties ของ Bridge ตั๋วเก่าจะใช้ไม่ได้ทันที (ผู้ใช้ต้องเข้าผ่าน Bridge ใหม่)
- แก้ `MAIN_URL` หรือโค้ดของ Bridge แล้วต้อง deploy เวอร์ชันใหม่ ไม่เช่นนั้น URL เดิมยังรันโค้ดเก่า

## ติดตั้ง

ใช้เวลาประมาณ 20–30 นาที ทำตามลำดับ

### ส่วน A: แอปหลัก

1. สร้าง Google Sheets ใหม่ 1 ไฟล์ (เช่น "เช็กชื่อ 2569") แล้วเปิด **ส่วนขยาย → Apps Script**
2. วางโค้ด `Code.gs` ทับไฟล์เดิม แล้วสร้างไฟล์เพิ่ม
   - **+ → สคริปต์** ชื่อ `Auth` วางโค้ดจาก `Auth.gs`
   - **+ → HTML** ชื่อ `Home`, `Teacher`, `Student`, `Admin` (ชื่อต้องตรงเป๊ะ ไม่ต้องพิมพ์ .html) วางโค้ดจากไฟล์ที่ตรงกัน
3. เปิดไฟล์ `appsscript.json` (เปิดได้ที่ **Project Settings → Show "appsscript.json" manifest file**) ให้เป็นแบบ **ไม่จำกัด `oauthScopes` แบบ `userinfo.email` อย่างเดียว** เพราะแอปหลักต้องเข้าถึง Sheets และ Cache/Lock/Properties
   - ตั้ง `webapp.executeAs` เป็น `USER_DEPLOYING` (Execute as: **Me**) และ `webapp.access` เป็น `ANYONE`
4. รันฟังก์ชัน `setup` ครั้งเดียว อนุญาตสิทธิ์ที่ถาม ระบบจะ
   - บันทึกรหัสไฟล์ชีตลง Script Properties (`SS_ID`)
   - สร้างชีต Students, Teachers, Sessions, Attendance, Admins, Adjustments, Schedule พร้อมหัวคอลัมน์
   - ใส่อีเมลของคุณเป็นอาจารย์และผู้ดูแลระบบคนแรก
   - ตั้งคอลัมน์รายชื่อนักเรียนเป็นข้อความล้วน (เก็บเลขศูนย์นำหน้า เช่น `01` ได้)
5. รันฟังก์ชัน `createAuthSecret` ครั้งเดียว แล้วเปิด **Execution log** คัดลอกค่า `AUTH_SECRET = ...` เก็บไว้ (ใช้ในส่วน B)
6. **Deploy → New deployment → Web app**: Execute as = **Me**, Who has access = **Anyone** แล้วคัดลอก URL ที่ลงท้าย `/exec` นี่คือ **MAIN_URL**

### ส่วน B: Bridge

1. สร้างโปรเจ็กต์ Apps Script ใหม่ (แยกจากส่วน A) วางโค้ด `Code.gs` ของ Bridge
2. ตั้ง `appsscript.json` ให้เป็น `executeAs: USER_ACCESSING`, `access: ANYONE` และ `oauthScopes` มี `https://www.googleapis.com/auth/userinfo.email`
3. **Project Settings → Script Properties** เพิ่มคีย์ `AUTH_SECRET` ใส่ค่าที่คัดลอกจากส่วน A ข้อ 5 (**ต้องตรงกันเป๊ะ**)
4. **Deploy → New deployment → Web app**: Execute as = **User accessing the web app**, Who has access = **Anyone** (หรือ Anyone with Google account) แล้วคัดลอก URL `/exec` นี่คือ **BRIDGE_URL**

### ส่วน C: เชื่อม 2 โปรเจ็กต์เข้าหากัน

เนื่องจากแต่ละฝั่งต้องรู้ URL ของอีกฝั่ง ให้กรอกแล้ว deploy เวอร์ชันใหม่:

| โปรเจ็กต์ | ไฟล์      | ค่าที่ต้องแก้                 |
| --------- | --------- | ----------------------------- |
| แอปหลัก   | `Auth.gs` | `BRIDGE_URL` = URL ของ Bridge |
| Bridge    | `Code.gs` | `MAIN_URL` = URL ของแอปหลัก   |

หลังแก้แล้วต้อง **Deploy → Manage deployments → ไอคอนแก้ไข → Version: New version → Deploy** ทั้ง 2 โปรเจ็กต์ (URL เดิมจะไม่เปลี่ยน) ถ้าไม่ทำ URL เดิมจะยังรันโค้ดเก่า

### ส่วน D: กรอกข้อมูลและทดสอบ

1. กรอกชีต **Students** (ดู [โครงสร้างชีต](#โครงสร้างชีต)) หรือรัน `seedDemo` เพื่อสร้างนักเรียนจำลอง 5 ห้อง × 40 คน (รันได้เฉพาะตอนที่ชีต Students ยังว่าง)
2. กรอกชีต **Teachers** และ **Admins** ด้วยอีเมลที่ได้รับสิทธิ์
3. เปิด `BRIDGE_URL` ด้วยบัญชีอาจารย์ → ควรเห็นหน้าแรกและเมนูตามสิทธิ์
4. ให้นักเรียนเปิด `BRIDGE_URL?p=ok` ครั้งเดียวบนมือถือ เพื่อกดอนุญาตบัญชีไว้ล่วงหน้า (ครั้งแรกที่ระบบขอสิทธิ์อ่านอีเมลจะมีหน้าขออนุญาต ถ้ากดตอนสแกนจริงจะเสียเวลาในคาบ)
5. **ทดสอบกับห้องจริงก่อนใช้จริง** (ดูหัวข้อโควตา)

> หลังแก้ชีต Students/Teachers/Admins ด้วยมือแล้วอยากให้มีผลทันที ให้รัน `clearCache` (ปกติแคชหมดอายุเองภายใน 5–10 นาที) การเพิ่ม/แก้/ลบนักเรียนผ่านหน้าแอดมินล้างแคชให้อัตโนมัติ

## ใช้งานในคาบเรียน

1. อาจารย์เปิด `BRIDGE_URL?p=t` (หรือกดจากหน้าแรก) → เลือกห้อง → ตั้งเวลาเปิดรับ (1–30 นาที ค่าเริ่มต้น 5) → **เริ่มเช็กชื่อ**
2. QR ขึ้นบนจอและเปลี่ยนทุก 15 วินาที มีแถบเวลาแสดงรอบที่เหลือ ถ้าเน็ตไม่เสถียรจะมีข้อความเตือนสีแดงใต้ QR
3. นักเรียนเปิดกล้องสแกน → เห็นหน้า "เช็กชื่อสำเร็จ ✓" พร้อมชื่อ เลขที่ ห้อง และเวลา (สแกนซ้ำจะขึ้น "เช็กชื่อไว้แล้ว")
4. อาจารย์ดูตัวเลข "เช็กแล้ว X / N" นาฬิกานับถอยหลัง และรายการ "ยังไม่เช็ก / เช็กแล้ว" ที่อัปเดตอัตโนมัติทุก 3 วินาที
5. ใครไม่มีมือถือหรือเน็ตมีปัญหา กด **ติ๊กให้** ในรายการ "ยังไม่เช็ก" (บันทึกเป็น `manual`) ถ้าพบการเช็กแทน กด **ยกเลิก** ที่รายการนั้น
6. ครบเวลาหรือกด **ปิดรับเช็กชื่อ** ระบบแสดงสรุป (เช็กแล้ว/ขาด) และยังติ๊ก/ยกเลิกต่อได้หลังปิดรอบ ข้อมูลทั้งหมดอยู่ในชีต **Attendance** กด **เริ่มรอบใหม่** เพื่อเปิดรอบถัดไป

ข้อความที่นักเรียนอาจเห็นเมื่อเช็กไม่สำเร็จ: QR หมดอายุ (ให้สแกนใหม่), ปิดรับเช็กชื่อแล้ว, ไม่พบอีเมลในรายชื่อ, บัญชีนี้ไม่ได้อยู่ในห้องของรอบนี้

## ระบบหลังบ้านสำหรับผู้ดูแลระบบ

เปิดด้วย `BRIDGE_URL?p=admin` (หรือกดการ์ด "สรุปผลการเช็กชื่อ" จากหน้าแรก) เมนูด้านซ้าย (บนมือถือเป็นเมนู ☰) มี 4 หน้า และปุ่ม "✅ เช็กชื่อ" ไปหน้าเช็กชื่อ

### 1) แดชบอร์ด

- คำทักทายตามช่วงเวลา นาฬิกา และวันที่ (พ.ศ.) แบบสด
- **ตารางสอนวันนี้**: เรียงตามคาบ พร้อมเน้นคาบปัจจุบัน (ป้าย "ขณะนี้") คาบที่ผ่านไปแล้วจางลง ถ้ายังไม่มีตารางสอนมีปุ่มลัดไปตั้งค่า
- **สรุปการเข้าเรียน 7 วันล่าสุด**: อัตราเข้าเรียนรวม จำนวนคาบที่เช็กแล้ว จำนวนมาสาย/ขาด (ปุ่มรีเฟรช)
- **แยกตามห้อง**: จำนวนคาบ อัตราเข้าเรียน และแถบสัดส่วนของแต่ละห้อง
- **นักเรียนที่ควรติดตาม**: อัตราเข้าเรียนต่ำกว่าเกณฑ์ และมีข้อมูลอย่างน้อย 3 คาบ (แสดงสูงสุด 8 คนที่ต่ำสุด)

### 2) ตารางสอน

- ตารางจันทร์–ศุกร์ × 8 คาบ พร้อมช่วงพัก (08:30–16:30) กดช่องเพื่อเพิ่ม/แก้ไข/ลบ
- กรอกวิชา ห้องเรียน สถานที่สอน และเลือก "สอนต่อเนื่องถึง" คาบใดก็ได้ ช่องเดิมในช่วงนั้นจะถูกแทนที่
- บนมือถือสลับเป็นมุมมองรายวัน (เลือกวัน)
- เวลาคาบกำหนดที่ค่าคงที่ `PERIODS` ใน `Admin.html`

### 3) รายชื่อนักเรียน

- เลือกห้อง ค้นหาด้วยเลขที่/ชื่อ/อีเมล แล้วกดแถวเพื่อแก้ไขหรือลบ ปุ่ม **+ เพิ่มนักเรียนใหม่** สำหรับเพิ่มรายคน
- ตรวจซ้ำให้ทุกครั้ง: อีเมลห้ามซ้ำทั้งระบบ เลขที่ห้ามซ้ำในห้องเดียวกัน
- **แก้อีเมลนักเรียน** ระบบย้ายประวัติเช็กชื่อ (Attendance) และการปรับสถานะ (Adjustments) ตามไปด้วย ไม่เช่นนั้นประวัติเดิมจะถูกนับเป็น "ขาด"
- **ลบนักเรียน** ลบเฉพาะแถวในชีต Students ประวัติเดิมยังอยู่ในชีต Attendance
- เรียงเลขที่แบบตัวเลขก่อน (2 มาก่อน 10) และเก็บค่าเป็นข้อความล้วน

### 4) รายงานผล

- เลือกห้อง ช่วงวันที่ หรือปุ่มด่วน (วันนี้ / 7 วัน / 30 วัน / ทั้งหมด) แล้วกดค้นหา (เปิดหน้ารายงานครั้งแรกจะโหลด 30 วันให้อัตโนมัติ)
- **ภาพรวม**: กราฟวงกลม (มา สาย ลา ขาด พร้อมจำนวนและ %) และกราฟแท่งแนวโน้ม (40 รายการล่าสุด) สลับ "รายคาบ / รายวัน" ได้
- แท็บ **แยกแต่ละคาบ**: ตารางสรุปแต่ละคาบหรือแต่ละวัน กดแถวเพื่อเปิดรายชื่อของรอบนั้น
- แท็บ **แยกรายบุคคล**: ตารางแบบสมุดเช็กชื่อ จัดคอลัมน์วันที่ตามเดือน (พ.ศ.) พร้อมสรุปท้ายแถว (มาเรียน, ป่วย/ลา, สาย, ขาด, รวมไม่มา, รวมเวลา, ร้อยละ) เรียงตามเลขที่ / % เข้าเรียน / จำนวนขาดได้ กดชื่อเพื่อดูประวัติรายคน กดช่องสถานะเพื่อเปิดรอบนั้นและแก้ไข
- **ดาวน์โหลด Excel**: ส่งออกตารางรายบุคคลเป็นไฟล์ `.xls` (สร้างจาก HTML) มีสูตรสรุปผลท้ายแถว (`COUNTIF`, `COUNTA`) Excel อาจเตือนเรื่องรูปแบบไฟล์ตอนเปิด ให้กดยืนยันเปิดได้ตามปกติ
- **ปรับสถานะ**: ในรายชื่อของแต่ละรอบ เปลี่ยนเป็น มาเรียน / มาสาย / ลา / ขาด พร้อมหมายเหตุ (เช่น ใบลาป่วย) บันทึกอัตโนมัติลงชีต Adjustments มีปุ่ม "คืนค่า" กลับไปตามระบบ
- **ยกเลิกรอบ (void)**: ใช้เมื่อเปิดรอบผิดหรือทดลองเท่านั้น รอบนั้นจะหายจากรายงานและแดชบอร์ดทันที (ข้อมูลยังอยู่ในชีต Sessions สถานะ `void`) และกู้คืนจากหน้าเว็บไม่ได้ ต้องแก้สถานะในชีตเอง

### หลักการนับสถานะ

รหัสสถานะ: `p` = มาเรียน (`/`), `l` = มาสาย (`ส`), `v` = ลา (`ล`), `a` = ขาด (`ข`)

- ลำดับความสำคัญ: **ที่แอดมินปรับ** > มีบันทึกสแกน/ติ๊กจากอาจารย์ = **มาเรียน** > ไม่มีบันทึก = **ขาด**
- ระบบตัดสินอัตโนมัติได้แค่ "มา" หรือ "ขาด" ส่วน **สาย** และ **ลา** มาจากการปรับสถานะโดยแอดมินเท่านั้น
- **อัตราเข้าเรียน = (มาเรียน + มาสาย) ÷ จำนวนทั้งหมด** การลาไม่นับเป็นเข้าเรียนแต่แยกแสดง
- แสดงสีแดงเมื่ออัตราต่ำกว่า 80%
- ไม่นับรอบที่ยังเปิดรับอยู่และรอบที่ถูก void

## ข้อจำกัดที่ควรรู้

- **ยังกัน 100% ไม่ได้**: เพื่อนที่นั่งในห้องใช้มือถือของตัวเองล็อกอินบัญชีเพื่อนอีกคนแล้วสแกนได้ ชั้นสุดท้ายคือการนับหัวของอาจารย์ รหัสอุปกรณ์เป็นสัญญาณเตือน ไม่ใช่หลักฐานเด็ดขาด (ล้างข้อมูลเบราว์เซอร์แล้วหลบได้)
- **โควตา Apps Script**: แอปหลักทำงานในนามเจ้าของสคริปต์ ทุกคำขอนับเป็นของเจ้าของ จำกัดการทำงานพร้อมกันประมาณ 30 รายการ นักเรียนแต่ละคนใช้หลายคำขอ (ผ่าน Bridge → เปิดหน้า → บันทึก) ถ้า 40 คนสแกนพร้อมกันเป๊ะ ๆ อาจมีบางคนต้องรอหรือสแกนซ้ำ ปกติสแกนเหลื่อมกันสองสามวินาทีจึงไม่น่ามีปัญหา แต่ **ควรทดสอบกับห้องจริงก่อนใช้จริง** ถ้าติดโควตาบ่อย ให้ย้ายหลังบ้านไป Firebase/Cloud Run
- **อายุตั๋วนักเรียน 10 นาที**: ถ้าเปิดหน้ารอไว้นานเกินกว่านั้นแล้วค่อยเช็ก ให้สแกน QR ใหม่
- **หลายบัญชีในมือถือ**: ถ้านักเรียนล็อกอิน Google หลายบัญชีในเบราว์เซอร์เดียว ลิงก์อาจเปิดด้วยบัญชีผิด ให้ใช้บัญชีที่ลงทะเบียนเป็นบัญชีหลัก หรือสแกนด้วยแอป Chrome ที่ล็อกอินบัญชีนั้น
- **สาย/ลา ต้องปรับด้วยมือ**: ระบบสแกนไม่แยกมาสาย ถ้าต้องการบันทึกสายหรือลา แอดมินปรับสถานะในหน้ารายงาน
- **ตารางสอนเป็นของแอดมินแต่ละคน**: ไม่ได้ผูกกับการเปิดรอบเช็กชื่ออัตโนมัติ (เป็นตารางเตือนความจำและแสดงบนแดชบอร์ด)
- **ความปลอดภัยของชีต**: ชีต `Sessions` เก็บคีย์ลับของ QR (คอลัมน์ F ซ่อนไว้) และ Script Properties เก็บ `AUTH_SECRET` แชร์ไฟล์ชีตให้เฉพาะผู้ดูแลเท่านั้น **อย่าแชร์ให้นักเรียน** และถ้ารหัสรั่วให้รัน `createAuthSecret` ใหม่ แล้วอัปเดตค่าใน Bridge
- **ข้อมูลส่วนบุคคล**: ระบบเก็บอีเมล เวลา และรหัสอุปกรณ์ ควรแจ้งนักเรียน/ผู้ปกครองล่วงหน้า

| `DEFAULT_MINUTES` / `MAX_MINUTES`          | เวลาเปิดรับเริ่มต้น / สูงสุด                                     | 5 / 30       |
| `TZ`                                       | เขตเวลาที่ใช้จัดรูปแบบวันที่ในรายงาน                             | Asia/Bangkok |
| `CACHE_STUDENTS_SEC` / `CACHE_SESSION_SEC` | อายุแคชรายชื่อนักเรียน / รอบเช็กชื่อ                             | 600 / 21600  |

**อื่น ๆ**

- `SCHEDULE_CFG` ใน `Code.gs`: `DAYS` (5), `PERIODS` (8), `LOW_RATE` (80)
- `LOW_RATE` ใน `Admin.html`: เกณฑ์ที่แสดงสีแดงในตารางรายงาน (**ถ้าเปลี่ยนเกณฑ์ ให้แก้ทั้ง 2 ที่ให้ตรงกัน**)
- `PERIODS` ใน `Admin.html`: เวลาเริ่ม–จบของแต่ละคาบและช่วงพัก
- `ttl` ใน `doGet` ของ Bridge: อายุตั๋วของหน้าเช็กชื่อ (10 นาที) และหน้าอื่น (8 ชั่วโมง)

ทุกครั้งที่แก้โค้ด ต้อง **Deploy → Manage deployments → แก้ไข → New version** ของโปรเจ็กต์นั้น

## แก้ปัญหาเบื้องต้น

| อาการ / ข้อความ                                           | สาเหตุและวิธีแก้                                                                                                       |
| --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| "ยังไม่ได้รัน setup()"                                    | ยังไม่ได้รันฟังก์ชัน `setup` ในแอปหลัก                                                                                 |
| "ยังไม่ได้ตั้งค่า AUTH_SECRET"                            | แอปหลัก: รัน `createAuthSecret` / Bridge: เพิ่ม `AUTH_SECRET` ใน Script Properties                                     |
| เข้าหน้าได้แต่ถูกเด้งวนไปมา หรือ "เซสชันหมดอายุ"          | `AUTH_SECRET` ของ 2 โปรเจ็กต์ไม่ตรงกัน, `MAIN_URL`/`BRIDGE_URL` ผิด, หรือยังไม่ได้ deploy เวอร์ชันใหม่                 |
| "อ่านอีเมลไม่ได้"                                         | Bridge ไม่ได้ตั้ง Execute as: User accessing, ขาดสโคป `userinfo.email`, หรือผู้ใช้ยังไม่ได้ล็อกอิน Google              |
| "บัญชีนี้ไม่มีสิทธิ์อาจารย์" / "เฉพาะผู้ดูแลระบบเท่านั้น" | เพิ่มอีเมลในชีต Teachers / Admins แล้วรัน `clearCache` (หรือรอ 5 นาที)                                                 |
| "ไม่พบอีเมลนี้ในรายชื่อนักเรียน"                          | อีเมลที่ล็อกอินไม่ตรงกับชีต Students (ตรวจตัวสะกดและตัวพิมพ์) หรือนักเรียนเปิดด้วยบัญชีผิด                             |
| "QR หมดอายุ"                                              | สแกนช้าเกินช่วงที่รับ ให้สแกนใหม่จากหน้าจอ ถ้าเกิดบ่อยให้เพิ่ม `GRACE_SLOTS`                                           |
| ข้อมูลนักเรียนในชีตเปลี่ยนแล้วแต่หน้าเว็บยังเป็นของเก่า   | รัน `clearCache`                                                                                                       |
| ผลการทดสอบยังเป็นโค้ดเก่า                                 | ยังไม่ได้ New version ในการ deploy                                                                                     |
| รายงานแสดง "ขาด" ย้อนหลังหลังเปลี่ยนอีเมลนักเรียน         | แก้อีเมลในชีต Students ด้วยมือ (ไม่ผ่านหน้าแอดมิน) ประวัติจึงไม่ถูกย้าย ให้แก้อีเมลใน Attendance/Adjustments ให้ตรงกัน |

รายละเอียดในชีต Attendance, Sessions และ Adjustments สามารถตรวจสอบย้อนหลังได้โดยตรง
