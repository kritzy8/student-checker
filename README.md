# ระบบเช็กชื่อด้วย QR Code หมุนเวียน

เว็บแอปสำหรับบันทึกการเข้าเรียนของนักเรียนด้วย QR Code ที่เปลี่ยนตามช่วงเวลา พัฒนาด้วย **Google Apps Script** และ **Google Sheets** พร้อมหน้าสำหรับอาจารย์และผู้ดูแลระบบ

ระบบประกอบด้วยการยืนยันตัวตนผ่าน Google Account, การเปิดรอบเช็กชื่อ, การแสดง QR Code แบบหมุนเวียน, การบันทึกการเข้าเรียน และเครื่องมือจัดการข้อมูล/รายงาน

## ความสามารถของระบบ

### สำหรับนักเรียน
- เข้าสู่ระบบด้วยบัญชี Google ที่ลงทะเบียนไว้ในรายชื่อนักเรียน
- สแกน QR Code จากหน้าจออาจารย์เพื่อเปิดหน้าเช็กชื่อ
- ระบบตรวจสอบบัญชี ห้องเรียน รอบเช็กชื่อ และโทเค็น QR ก่อนบันทึก
- ป้องกันการบันทึกซ้ำจากบัญชีเดิมภายในรอบเดียวกัน
- บันทึกเวลาและข้อมูลอุปกรณ์ที่ใช้เช็กชื่อ

### สำหรับอาจารย์
- เปิดรอบเช็กชื่อโดยเลือกห้องเรียนและระยะเวลารับเช็กชื่อ
- แสดง QR Code ที่เปลี่ยนโทเค็นทุก 15 วินาที
- แสดงจำนวนผู้เช็กชื่อและรายชื่อผู้ที่เช็กแล้ว/ยังไม่เช็ก
- ปิดรอบเช็กชื่อเมื่อเสร็จสิ้น
- ยกเลิกการเช็กชื่อรายบุคคลได้จากหน้าจอรอบ

### สำหรับผู้ดูแลระบบ
- ดูแดชบอร์ดสรุปภาพรวมการเข้าเรียน
- จัดการตารางสอนรายวันและรายคาบ
- เพิ่ม แก้ไข และลบนักเรียน
- ดูรายงานการเข้าเรียนตามห้องและช่วงวันที่
- ดูข้อมูลภาพรวม รายคาบ/รายวัน และรายบุคคล
- ปรับสถานะ มาเรียน / มาสาย / ลา / ขาด พร้อมหมายเหตุ
- ดาวน์โหลดรายงานรายบุคคลเป็นไฟล์ Excel `.xlsx`
- ยกเลิกรอบเช็กชื่อที่เปิดผิดหรือใช้ทดสอบ

## สถาปัตยกรรมและไฟล์

ระบบใช้ Apps Script **2 โปรเจ็กต์แยกกัน** เพื่อแยกหน้าที่ระหว่างการอ่านอีเมลผู้ใช้กับการเข้าถึงฐานข้อมูล

| โปรเจ็กต์ | หน้าที่ | ไฟล์ |
|---|---|---|
| แอปหลัก (Main) | แสดงหน้าเว็บ จัดการข้อมูล ตรวจสิทธิ์ และทำงานกับ Google Sheets | `Code.gs`, `Auth.gs`, `Home.html`, `Teacher.html`, `Student.html`, `Admin.html`, `appsscript.json` |
| Bridge | อ่านอีเมล Google ของผู้ใช้ สร้างตั๋วยืนยันตัวตน และส่งผู้ใช้ไปยังแอปหลัก | `Code.gs` ของ Bridge และ `appsscript.json` ของ Bridge |

> ไฟล์ `Code.gs` ของ Main และ Bridge เป็นคนละไฟล์ แม้ชื่อเหมือนกัน ต้องนำไปวางใน Apps Script คนละโปรเจ็กต์ อย่าสลับกัน

### ลำดับการทำงาน

```text
ผู้ใช้
  │
  ▼
Bridge
อ่านอีเมล Google และสร้าง Auth Ticket ที่ลงลายเซ็น HMAC-SHA256
  │
  ▼
แอปหลัก (Main)
ตรวจสอบ Ticket และสิทธิ์ผู้ใช้
  │
  ├── นักเรียน: หน้าเช็กชื่อ
  ├── อาจารย์: หน้าเปิดรอบและแสดง QR
  └── ผู้ดูแล: แดชบอร์ด จัดการข้อมูล และรายงาน
  │
  ▼
Google Sheets
จัดเก็บรายชื่อ รอบเช็กชื่อ ประวัติ และการปรับสถานะ
```

### การยืนยันตัวตน

Bridge ทำงานในนามผู้เข้าชม (Execute as: **User accessing the web app**) จึงสามารถอ่านอีเมลจากบัญชี Google ที่ล็อกอินอยู่ได้ ส่วนแอปหลักทำงานในนามเจ้าของสคริปต์ (Execute as: **Me**) เพื่อเข้าถึง Google Sheets

Bridge สร้าง Auth Ticket โดยใช้ `AUTH_SECRET` และลายเซ็น HMAC-SHA256 จากนั้นส่งต่อไปยัง Main แอปหลักจะตรวจลายเซ็นและเวลาหมดอายุก่อนให้ใช้งาน

- Ticket สำหรับหน้าเช็กชื่อของนักเรียน (`p=c`) มีอายุ 10 นาที
- Ticket สำหรับหน้าอื่น เช่น หน้าแรก อาจารย์ และผู้ดูแลระบบ มีอายุ 8 ชั่วโมง
- `AUTH_SECRET` ใน Main และ Bridge ต้องตรงกันทุกตัวอักษร
- Ticket เป็นข้อมูลที่อยู่ใน URL ไม่ใช่รหัสผ่าน และไม่ควรส่งต่อให้ผู้อื่น

### พารามิเตอร์หน้าเว็บ

| พารามิเตอร์ | หน้า |
|---|---|
| ไม่ระบุ `p` | หน้าแรกและเมนูตามสิทธิ์ |
| `p=t` | หน้าอาจารย์สำหรับเปิดรอบเช็กชื่อ |
| `p=admin` | หน้าผู้ดูแลระบบ |
| `p=c` | หน้าเช็กชื่อของนักเรียน โดยใช้พารามิเตอร์รอบและโทเค็น QR |
| `p=ok` | หน้าเตรียมอนุญาตให้ Bridge อ่านอีเมล Google ในการเข้าใช้งานครั้งแรก |

ควรแจกจ่ายลิงก์ของ **Bridge** เป็นจุดเริ่มต้นให้ผู้ใช้เสมอ หากเปิด Main โดยไม่มี Ticket ระบบจะส่งผู้ใช้ไปยืนยันตัวตนผ่าน Bridge

## สิ่งที่ต้องเตรียม

1. บัญชี Google สำหรับเจ้าของระบบ ซึ่งเป็นเจ้าของ Google Sheets และ Apps Script ทั้งสองโปรเจ็กต์
2. Google Sheets หนึ่งไฟล์สำหรับเก็บข้อมูล
3. รายชื่อและอีเมล Google ของนักเรียน
4. รายชื่ออีเมลอาจารย์และผู้ดูแลระบบ
5. ผู้ใช้งานต้องล็อกอิน Google Account ที่ตรงกับอีเมลที่ลงทะเบียนไว้
6. แนะนำให้ใช้งานผ่านเบราว์เซอร์ Chrome ที่อัปเดตแล้ว ทั้งบนคอมพิวเตอร์และโทรศัพท์

## ติดตั้งและตั้งค่า

การติดตั้งต้องสร้าง Apps Script 2 โปรเจ็กต์ ได้แก่ Main และ Bridge และเชื่อม URL ระหว่างกัน

### A. สร้างแอปหลัก (Main)

1. สร้าง Google Sheets ใหม่
2. เปิดเมนู **ส่วนขยาย → Apps Script**
3. นำโค้ดจากไฟล์ `Code.gs` ของ Main ไปวางในโปรเจ็กต์
4. สร้างไฟล์สคริปต์ชื่อ `Auth` แล้ววางโค้ดจาก `Auth.gs`
5. สร้างไฟล์ HTML ชื่อ `Home`, `Teacher`, `Student` และ `Admin` แล้ววางโค้ดจากไฟล์ HTML ที่ตรงกัน
6. เปิด **Project Settings → Show "appsscript.json" manifest file** เพื่อตรวจสอบ Manifest ของ Main ให้ตั้งค่า Web App ให้ทำงานในนามเจ้าของสคริปต์ (`USER_DEPLOYING`) และเข้าถึงตามการตั้งค่าที่ระบบต้องใช้ อย่านำ Manifest ของ Bridge มาใช้แทน Main
7. เลือกฟังก์ชัน `setup` แล้วกด Run พร้อมอนุญาตสิทธิ์ที่ Google ขอ ระบบจะบันทึก ID ของ Spreadsheet และสร้างชีตที่จำเป็น
8. เลือกฟังก์ชัน `createAuthSecret` แล้วกด Run จากนั้นคัดลอกค่าที่แสดงใน Execution log เก็บไว้สำหรับตั้งค่า Bridge
9. เลือก **Deploy → New deployment → Web app**
   - Execute as: **Me**
   - Who has access: เลือกการเข้าถึงที่เหมาะสมกับนโยบายของสถานศึกษา โดยต้องสอดคล้องกับการใช้งานผ่าน Bridge
10. คัดลอก URL ที่ลงท้ายด้วย `/exec` เก็บไว้เป็น `MAIN_URL`

หลัง `setup` ระบบจะสร้างชีต `Students`, `Teachers`, `Sessions`, `Attendance`, `Admins`, `Adjustments` และ `Schedule` พร้อมหัวคอลัมน์ และเพิ่มบัญชีเจ้าของระบบเป็นอาจารย์/ผู้ดูแลระบบเริ่มต้น

### B. สร้าง Bridge

1. สร้าง Apps Script โปรเจ็กต์ใหม่ แยกจาก Main
2. วางโค้ดจากไฟล์ `Code(1).gs` ซึ่งเป็นโค้ด Bridge ลงในไฟล์ `Code.gs` ของโปรเจ็กต์ใหม่นี้
3. เปิด `appsscript.json` ของ Bridge และตั้งค่าให้ทำงานในนามผู้เข้าชม (`USER_ACCESSING`) พร้อม OAuth scope สำหรับอ่านอีเมล Google:
   `https://www.googleapis.com/auth/userinfo.email`
4. เปิด **Project Settings → Script Properties** แล้วเพิ่ม Property:
   - Key: `AUTH_SECRET`
   - Value: ค่าที่ได้จาก `createAuthSecret` ใน Main
5. เลือก **Deploy → New deployment → Web app**
   - Execute as: **User accessing the web app**
   - Who has access: ตั้งตามนโยบายการใช้งานที่ต้องการ โดยต้องอนุญาตให้ผู้ใช้ที่เกี่ยวข้องเข้าถึง Bridge ได้
6. คัดลอก URL `/exec` เก็บไว้เป็น `BRIDGE_URL`

### C. เชื่อม Main และ Bridge

แก้ URL ในไฟล์ของแต่ละโปรเจ็กต์ให้ถูกต้อง

| โปรเจ็กต์ | ไฟล์ | ค่าที่ต้องกำหนด |
|---|---|---|
| Main | `Auth.gs` | `BRIDGE_URL` = URL ของ Bridge |
| Bridge | `Code.gs` | `MAIN_URL` = URL ของ Main |

จากนั้น Deploy โปรเจ็กต์ทั้งสองใหม่เป็น **New version** ผ่านเมนู **Deploy → Manage deployments → Edit → New version → Deploy**

> เมื่อแก้โค้ดหรือ URL แล้ว การบันทึกไฟล์อย่างเดียวไม่ทำให้ Web App ที่ Deploy อยู่เปลี่ยนตาม ต้อง Deploy เป็นเวอร์ชันใหม่ด้วย

### D. เตรียมบัญชีผู้ใช้และทดสอบ

1. เพิ่มอีเมลนักเรียนลงในชีต `Students`
2. เพิ่มอีเมลอาจารย์ลงในชีต `Teachers`
3. เพิ่มอีเมลผู้ดูแลระบบลงในชีต `Admins`
4. ให้นักเรียนเปิด `BRIDGE_URL?p=ok` หนึ่งครั้ง เพื่อเข้าสู่ขั้นตอนอนุญาตให้ Bridge อ่านอีเมล Google
5. ทดสอบด้วยบัญชีอาจารย์: เปิดหน้าอาจารย์ เลือกห้อง เปิดรอบ และตรวจว่า QR แสดงผล
6. ทดสอบด้วยบัญชีนักเรียน: สแกน QR และตรวจว่ารายการถูกบันทึกในหน้าอาจารย์และชีต `Attendance`
7. ทดสอบด้วยบัญชีผู้ดูแล: เปิดหน้า Admin ตรวจรายชื่อ ตารางสอน รายงาน และการดาวน์โหลด Excel

ควรทดสอบด้วยบัญชีจริงและจำนวนผู้ใช้ใกล้เคียงกับการใช้งานจริงก่อนเริ่มใช้ในชั้นเรียน

## โครงสร้าง Google Sheets

ฟังก์ชัน `setup` สร้างชีตหลักดังนี้

| ชีต | หน้าที่ |
|---|---|
| `Students` | รายชื่อนักเรียน ห้อง เลขที่ และอีเมล |
| `Teachers` | รายชื่ออีเมลที่ได้รับสิทธิ์อาจารย์ |
| `Admins` | รายชื่ออีเมลที่ได้รับสิทธิ์ผู้ดูแลระบบ |
| `Sessions` | ข้อมูลรอบเช็กชื่อ เช่น ห้อง เวลาเปิด/ปิด และข้อมูลที่ใช้ตรวจสอบ QR |
| `Attendance` | ประวัติการเช็กชื่อของนักเรียนในแต่ละรอบ |
| `Adjustments` | ประวัติการปรับสถานะโดยผู้ดูแลระบบ |
| `Schedule` | ตารางสอนที่ใช้แสดงในแดชบอร์ด |

`setup` จะบันทึก Spreadsheet ID ไว้ใน Script Properties ของ Main ภายใต้คีย์ `SS_ID`

**ข้อควรระวัง:** ชีต `Sessions` มีข้อมูลลับที่ใช้ตรวจสอบ QR (มีคอลัมน์ที่ซ่อนไว้) และ Script Properties มี `AUTH_SECRET` จึงไม่ควรแชร์ Spreadsheet หรือสิทธิ์แก้ไข Apps Script ให้กับนักเรียน

## สิทธิ์การใช้งาน

ระบบตรวจสอบสิทธิ์จากอีเมล Google ที่ Bridge ส่งมา และตรวจซ้ำที่ฝั่งเซิร์ฟเวอร์

| กลุ่มผู้ใช้ | แหล่งข้อมูลสิทธิ์ | การใช้งาน |
|---|---|---|
| นักเรียน | `Students` | เข้าใช้หน้าเช็กชื่อได้เมื่ออีเมลตรงกับรายชื่อและห้องของรอบ |
| อาจารย์ | `Teachers` | เปิดและควบคุมรอบเช็กชื่อ |
| ผู้ดูแลระบบ | `Admins` | จัดการรายชื่อนักเรียน ตารางสอน รายงาน และการปรับสถานะ |

การซ่อนเมนูบนหน้าเว็บไม่ใช่มาตรการรักษาความปลอดภัยเพียงอย่างเดียว ฟังก์ชัน API มี whitelist และตรวจสิทธิ์ซ้ำก่อนดำเนินการ

## วิธีใช้งาน

### อาจารย์: เปิดรอบเช็กชื่อ

1. เปิดลิงก์ Bridge ของระบบ
2. เลือกหน้าอาจารย์
3. เลือกห้องเรียนและกำหนดระยะเวลารับเช็กชื่อ
4. กดเริ่มรอบ ระบบจะแสดง QR Code บนหน้าจอ
5. ให้นักเรียนสแกน QR จากหน้าจอ
6. ตรวจจำนวนผู้เช็กชื่อและรายชื่อผู้ที่เช็กแล้ว/ยังไม่เช็ก
7. กดปิดรอบเมื่อเสร็จสิ้น

QR Code จะเปลี่ยนโทเค็นทุก 15 วินาที หน้าจออาจารย์จะอัปเดตสถานะผู้เช็กชื่อเป็นระยะ

### นักเรียน: เช็กชื่อ

1. ล็อกอิน Google Account ที่ลงทะเบียนไว้ใน `Students`
2. เปิดกล้องหรือแอปสแกน QR บนโทรศัพท์
3. สแกน QR จากหน้าจออาจารย์
4. ระบบจะเปิดหน้าตรวจสอบตัวตนและบันทึกการเช็กชื่อ
5. หาก QR หมดอายุ ให้สแกน QR ปัจจุบันอีกครั้ง

### ผู้ดูแลระบบ: จัดการข้อมูล

#### แดชบอร์ด
- แสดงภาพรวมการเช็กชื่อและข้อมูลที่เกี่ยวข้องกับการเข้าเรียน
- แสดงรายการที่ควรติดตาม โดยพิจารณานักเรียนที่มีอัตราเข้าเรียนต่ำกว่าเกณฑ์และมีข้อมูลการเข้าเรียนอย่างน้อย 3 คาบ (แสดงรายการอัตราต่ำสุดได้สูงสุด 8 คน)

#### ตารางสอน
- ตารางวันจันทร์–ศุกร์ จำนวน 8 คาบ ในช่วงเวลา 08:30–16:30 น. รวมช่วงพัก
- คลิกช่องเพื่อเพิ่ม แก้ไข หรือลบรายการสอน
- ระบุวิชา ห้องเรียน สถานที่ และคาบสุดท้ายของการสอนต่อเนื่องได้
- เมื่อกำหนดช่วงคาบต่อเนื่อง ช่องเดิมในช่วงดังกล่าวจะถูกแทนที่
- บนโทรศัพท์สามารถเปลี่ยนเป็นมุมมองรายวันได้
- ตารางสอนเป็นข้อมูลประกอบแดชบอร์ด ไม่ได้เปิดรอบเช็กชื่อให้อัตโนมัติ

#### รายชื่อนักเรียน
- เลือกห้องและค้นหาด้วยเลขที่ ชื่อ หรืออีเมล
- เพิ่มนักเรียนใหม่ แก้ไขข้อมูล หรือลบนักเรียน
- อีเมลต้องไม่ซ้ำกันทั้งระบบ และเลขที่ต้องไม่ซ้ำภายในห้องเดียวกัน
- การแก้ไขอีเมลผ่านหน้า Admin จะย้ายข้อมูลที่เกี่ยวข้องใน `Attendance` และ `Adjustments` ตามไปยังอีเมลใหม่
- การลบนักเรียนจะลบแถวจาก `Students` แต่ประวัติเดิมใน `Attendance` ยังคงอยู่
- เลขที่ถูกเก็บเป็นข้อความ เพื่อรองรับเลขศูนย์นำหน้า เช่น `01` และเรียงลำดับเชิงตัวเลข เช่น 2 ก่อน 10

> หากแก้อีเมลนักเรียนโดยแก้เซลล์ใน Google Sheets โดยตรง ระบบจะไม่ย้ายประวัติย้อนหลังให้โดยอัตโนมัติ ควรแก้ผ่านหน้า Admin

#### รายงานผล
- เลือกห้องและช่วงวันที่ หรือใช้ตัวกรองด่วน วันนี้ / 7 วัน / 30 วัน / ทั้งหมด
- เมื่อเปิดหน้ารายงานครั้งแรก ระบบโหลดข้อมูลย้อนหลัง 30 วันเป็นค่าเริ่มต้น
- ภาพรวมแสดงกราฟสรุปสถานะและแนวโน้มการเข้าเรียน โดยเลือกมุมมองรายคาบหรือรายวันได้
- แท็บรายคาบ/รายวันแสดงสรุปแต่ละรอบ สามารถเปิดดูรายชื่อของรอบนั้นได้
- แท็บรายบุคคลแสดงข้อมูลในรูปแบบสมุดเช็กชื่อ แยกคอลัมน์ตามวันที่และสรุปจำนวนสถานะท้ายแถว
- สามารถเรียงข้อมูลตามเลขที่ อัตราเข้าเรียน หรือจำนวนครั้งที่ขาดได้
- คลิกชื่อนักเรียนเพื่อดูประวัติรายบุคคล และคลิกช่องสถานะเพื่อเปิดรายละเอียดรอบและปรับสถานะ

#### ดาวน์โหลด Excel
- ส่งออกตารางรายบุคคลเป็นไฟล์ `.xlsx` จริง โดยใช้ ExcelJS 4.4.0
- ไฟล์ประกอบด้วยตารางรายวัน/รายคาบและสูตรสรุปผล เช่น `COUNTIF` และ `COUNTA`
- มีการจัดรูปแบบตาราง แช่แข็งแถว/คอลัมน์หัวตาราง และกำหนดการพิมพ์แนวนอนให้พอดีกับความกว้างหนึ่งหน้า
- มีการจัดรูปแบบตามสถานะและเน้นอัตราเข้าเรียนที่ต่ำกว่าเกณฑ์
- การสร้างไฟล์โหลดไลบรารี ExcelJS จาก CDN จึงต้องเชื่อมต่ออินเทอร์เน็ต หากดาวน์โหลดไม่ได้ให้ตรวจสอบเครือข่ายหรือการเข้าถึง CDN

#### ปรับสถานะและยกเลิกรอบ
- ผู้ดูแลระบบสามารถปรับสถานะของนักเรียนในแต่ละรอบเป็น มาเรียน / มาสาย / ลา / ขาด พร้อมหมายเหตุ
- การปรับสถานะจะบันทึกใน `Adjustments` และมีคำสั่งคืนค่าให้กลับไปใช้ผลจากระบบเดิม
- การยกเลิกรอบ (void) เหมาะสำหรับรอบที่เปิดผิดหรือใช้ทดสอบ รอบดังกล่าวจะไม่ถูกรวมในแดชบอร์ดและรายงาน แต่ข้อมูลรอบยังคงอยู่ใน `Sessions`
- การยกเลิกรอบไม่สามารถคืนค่าผ่านหน้าเว็บได้ หากจำเป็นต้องกู้คืนต้องตรวจสอบและแก้ไขข้อมูลในชีตอย่างระมัดระวัง

## หลักการคำนวณสถานะ

รหัสสถานะที่ใช้ในระบบ:

| รหัส | ความหมาย | สัญลักษณ์ |
|---|---|---|
| `p` | มาเรียน | `/` |
| `l` | มาสาย | `ส` |
| `v` | ลา | `ล` |
| `a` | ขาด | `ข` |

ลำดับการตัดสินสถานะ:

1. หากมีการปรับสถานะโดยผู้ดูแลระบบ ให้ใช้สถานะจาก `Adjustments`
2. หากไม่มีการปรับสถานะ แต่มีบันทึกการสแกนหรืออาจารย์ติ๊กเช็กชื่อ ให้ถือว่า **มาเรียน**
3. หากไม่มีบันทึกการเข้าเรียน ให้ถือว่า **ขาด**

ข้อกำหนดการคำนวณ:

- ระบบอัตโนมัติตัดสินได้เฉพาะมาเรียนหรือขาด
- สถานะมาสายและลาต้องให้ผู้ดูแลระบบปรับด้วยตนเอง
- อัตราเข้าเรียน = (จำนวนมาเรียน + จำนวนมาสาย) ÷ จำนวนทั้งหมด
- การลาแสดงแยกต่างหากและไม่นับเป็นการเข้าเรียน
- อัตราเข้าเรียนต่ำกว่า 80% จะแสดงเป็นสีแดงตามเกณฑ์ปัจจุบัน
- รอบที่ยังเปิดรับเช็กชื่อและรอบที่มีสถานะ `void` จะไม่ถูกนำมาคำนวณในรายงาน

## การปรับแต่ง

ค่าหลักอยู่ในส่วน `CONFIG` ของ `Code.gs` ในโปรเจ็กต์ Main

| ค่า | ความหมาย | ค่าปัจจุบัน |
|---|---|---:|
| `SLOT_SECONDS` | ระยะเวลาต่อโทเค็น QR | 15 วินาที |
| `GRACE_SLOTS` | จำนวนช่วงเวลาก่อนหน้าที่ยอมรับ | 2 |
| `DEFAULT_MINUTES` | ระยะเวลาเปิดรอบเริ่มต้น | 5 นาที |
| `MAX_MINUTES` | ระยะเวลาเปิดรอบสูงสุด | 30 นาที |
| `TZ` | เขตเวลาสำหรับการจัดรูปแบบวันที่ | `Asia/Bangkok` |
| `CACHE_STUDENTS_SEC` | อายุแคชรายชื่อนักเรียน | 600 วินาที |
| `CACHE_SESSION_SEC` | อายุแคชข้อมูลรอบเช็กชื่อ | 21600 วินาที |

ค่าที่เกี่ยวข้องอื่น ๆ:

- `SCHEDULE_CFG` ใน `Code.gs` กำหนดจำนวนวัน จำนวนคาบ และเกณฑ์อัตราเข้าเรียน
- `LOW_RATE` ใน `Admin.html` ใช้กำหนดเกณฑ์สีแดงในตารางรายงาน หากเปลี่ยนเกณฑ์ควรตรวจให้ตรงกับค่าที่กำหนดใน `Code.gs`
- `PERIODS` ใน `Admin.html` กำหนดเวลาเริ่ม–สิ้นสุดของแต่ละคาบและช่วงพัก
- ค่าอายุ Auth Ticket อยู่ใน `doGet` ของ Bridge (นักเรียน 10 นาที และหน้าอื่น 8 ชั่วโมง)

หลังแก้ไขไฟล์ใด ต้อง Deploy โปรเจ็กต์นั้นเป็น New version เพื่อให้ Web App ใช้โค้ดล่าสุด

## การสำรองและดูแลข้อมูล

ข้อมูลหลักทั้งหมดเก็บอยู่ใน Google Sheets จึงควรสำรองไฟล์ Spreadsheet เป็นระยะ โดยเฉพาะก่อนแก้ไขข้อมูลจำนวนมากหรือปรับโครงสร้างชีต

แนวทางที่แนะนำ:

1. ใช้ **File → Make a copy** เพื่อสำรอง Spreadsheet ก่อนการเปลี่ยนแปลงครั้งใหญ่
2. จำกัดสิทธิ์เข้าถึง Spreadsheet ให้เฉพาะผู้ดูแลที่จำเป็น
3. หลีกเลี่ยงการลบแถวหรือเปลี่ยนชื่อหัวคอลัมน์ในชีตระบบเอง เพราะโค้ดอาจอ้างอิงตำแหน่งหรือชื่อคอลัมน์เหล่านั้น
4. ตรวจสอบ `Attendance`, `Sessions` และ `Adjustments` เมื่อต้องตรวจสอบประวัติย้อนหลัง
5. เก็บ `AUTH_SECRET` ไว้ใน Script Properties และไม่เผยแพร่ใน README, แชต หรือแหล่งเก็บโค้ดสาธารณะ
6. หากสงสัยว่า `AUTH_SECRET` รั่ว ให้รัน `createAuthSecret` ใน Main แล้วนำค่าชุดใหม่ไปแทนที่ Script Property `AUTH_SECRET` ใน Bridge จากนั้นตรวจสอบและ Deploy โค้ดที่เกี่ยวข้องใหม่

## ข้อจำกัด

- **ไม่สามารถป้องกันการเช็กชื่อแทนได้ 100%** หากนักเรียนที่อยู่ในห้องล็อกอินด้วยบัญชีของเพื่อนบนอุปกรณ์ของตนเองแล้วสแกน QR ระบบอาจตรวจไม่พบ การตรวจอุปกรณ์ซ้ำเป็นเพียงสัญญาณเตือน ไม่ใช่หลักฐานยืนยันตัวบุคคล
- **ประสิทธิภาพขึ้นกับโควตา Google Apps Script** แอปหลักทำงานในนามเจ้าของสคริปต์ คำขอจากผู้ใช้จึงใช้โควตาของเจ้าของระบบ หากมีผู้ใช้จำนวนมากส่งคำขอพร้อมกันอาจเกิดความล่าช้าหรือจำเป็นต้องสแกนใหม่ ควรทดสอบกับจำนวนผู้ใช้จริงก่อนใช้งาน
- **Auth Ticket ของนักเรียนมีอายุ 10 นาที** หากเปิดหน้าเช็กชื่อค้างไว้นานจน Ticket หมดอายุ ควรสแกน QR ใหม่
- **เบราว์เซอร์ที่ล็อกอินหลายบัญชี Google** อาจเลือกบัญชีผิด ควรตรวจสอบบัญชีที่ใช้งานหรือใช้ Chrome โปรไฟล์ที่ล็อกอินบัญชีที่ลงทะเบียนไว้
- **ระบบไม่แยกมาสายโดยอัตโนมัติ** การเช็กผ่าน QR จะบันทึกเป็นมาเรียน ส่วนมาสายและลาต้องปรับโดยผู้ดูแลระบบ
- **ตารางสอนไม่ได้ควบคุมรอบเช็กชื่อ** เป็นข้อมูลประกอบและแสดงผลบนแดชบอร์ดเท่านั้น
- **การส่งออก Excel ต้องใช้อินเทอร์เน็ต** เพราะหน้า Admin โหลด ExcelJS จาก CDN
- **ข้อมูลส่วนบุคคล** ระบบจัดเก็บอีเมล เวลาเช็กชื่อ และข้อมูลอุปกรณ์ ควรแจ้งผู้เรียน/ผู้ปกครองและดำเนินการตามนโยบายคุ้มครองข้อมูลของสถานศึกษา

## แก้ปัญหาเบื้องต้น

| อาการ / ข้อความ | สาเหตุที่เป็นไปได้และวิธีแก้ |
|---|---|
| `ยังไม่ได้รัน setup()` | รัน `setup` ในโปรเจ็กต์ Main และตรวจว่า Script Properties มี `SS_ID` |
| `ยังไม่ได้ตั้งค่า AUTH_SECRET` | รัน `createAuthSecret` ใน Main และตั้งค่า Script Property `AUTH_SECRET` ใน Bridge |
| เข้าหน้าแล้วเด้งวน หรือแจ้งว่าเซสชันหมดอายุ | ตรวจ `AUTH_SECRET` ของทั้งสองโปรเจ็กต์, `MAIN_URL`, `BRIDGE_URL` และตรวจว่า Deploy เป็น New version แล้ว |
| `อ่านอีเมลไม่ได้` | ตรวจว่า Bridge ตั้ง Execute as เป็น User accessing, มี OAuth scope `userinfo.email` และผู้ใช้ล็อกอิน Google แล้ว |
| ไม่มีสิทธิ์อาจารย์/ผู้ดูแล | ตรวจอีเมลในชีต `Teachers` หรือ `Admins` ให้ตรงกับบัญชีที่ล็อกอิน แล้วรัน `clearCache` |
| ไม่พบอีเมลในรายชื่อนักเรียน | ตรวจอีเมลใน `Students` และตรวจว่าผู้ใช้เปิดด้วยบัญชี Google ที่ลงทะเบียนไว้ |
| `QR หมดอายุ` | สแกน QR ปัจจุบันใหม่ หากเกิดบ่อยให้ตรวจเครือข่ายและค่า `GRACE_SLOTS` |
| แก้ข้อมูลในชีตแล้วหน้าเว็บยังแสดงข้อมูลเดิม | รัน `clearCache` ใน Main |
| หน้าเว็บยังใช้โค้ดเก่า | Deploy โปรเจ็กต์ที่แก้ไขเป็น New version |
| รายงานแสดงขาดหลังแก้อีเมลด้วยมือในชีต | แก้ไขอีเมลผ่านหน้า Admin เพื่อย้ายประวัติ หรือปรับข้อมูลอ้างอิงใน `Attendance` และ `Adjustments` ให้ตรงกันอย่างระมัดระวัง |
| ดาวน์โหลด Excel ไม่สำเร็จ | ตรวจการเชื่อมต่ออินเทอร์เน็ตและการเข้าถึง CDN ที่ใช้โหลด ExcelJS |

## หมายเหตุสำหรับผู้พัฒนา

- อย่าเปิดเผย `AUTH_SECRET` หรือ Ticket ที่มีพารามิเตอร์ `auth=` ในเอกสารสาธารณะ
- อย่าแชร์ Google Sheets ฐานข้อมูลให้บัญชีนักเรียน
- ก่อนเปลี่ยนชื่อชีต หัวคอลัมน์ หรือโครงสร้างข้อมูล ให้ตรวจสอบจุดที่โค้ดเรียกใช้งานก่อน
- เมื่อเพิ่มหรือเปลี่ยนฟังก์ชัน API ให้ตรวจสอบ whitelist และการตรวจสิทธิ์ใน `Auth.gs` ด้วย
- หลังแก้โค้ด ให้ทดสอบทั้งบทบาทนักเรียน อาจารย์ และผู้ดูแลระบบก่อน Deploy ใช้งานจริง
