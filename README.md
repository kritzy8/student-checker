## 1. ภาพรวมและความสามารถ

### นักเรียน

- ล็อกอินด้วยบัญชี Google ที่ลงทะเบียนไว้ ไม่ต้องพิมพ์ชื่อหรือรหัส
- สแกน QR จากหน้าจอหน้าห้อง ระบบตรวจ บัญชี ห้องเรียน รอบ และโทเค็น แล้วบันทึกให้ทันที
- เช็กได้ครั้งเดียวต่อรอบ สแกนซ้ำจะแจ้งว่า "เช็กชื่อไว้แล้ว" พร้อมเวลาเดิม
- ถ้าเซิร์ฟเวอร์ติดคิวเขียนข้อมูล (เช่น สแกนพร้อมกันทั้งห้อง) หน้าจะลองใหม่ให้อัตโนมัติสูงสุด 2 ครั้ง

### อาจารย์

- เลือกห้อง (ต้องเลือกเองก่อน ปุ่มเริ่มจะเป็นสีเทาจนกว่าจะเลือก) และกำหนดเวลาเปิดรับ 1–30 นาที ด้วยปุ่ม −/+ แถบเลื่อน หรือปุ่มลัด 5/10/15/30 นาที
- แสดง QR ที่เปลี่ยนทุก 10 วินาที พร้อมแถบนับถอยหลังและเวลาที่เหลือของรอบ (เหลือ ≤ 1 นาทีจะเปลี่ยนเป็นสีเหลือง)
- เห็นจำนวนผู้เช็กแล้ว/ยังไม่เช็ก และรายชื่อสองฝั่งแบบเรียลไทม์ (อัปเดตทุก 3 วินาที) ค้นหาด้วยชื่อหรือเลขที่ได้
- **ติ๊กให้นักเรียน** ที่ไม่มีมือถือหรือเน็ตมีปัญหา (บันทึกวิธีเป็น `manual`)
- **ยกเลิกการเช็ก** รายบุคคล กรณีตรวจพบการเช็กแทนกัน
- แจ้งเตือน ⚠ "อุปกรณ์ซ้ำ" เมื่อพบอุปกรณ์เดียวกันเช็กหลายบัญชี
- ถ้าเปิดหน้าใหม่แล้วเลือกห้องที่ตนเองมีรอบเปิดค้างอยู่ ระบบจะ **กลับเข้ารอบเดิมต่อ** แทนการสร้างรอบซ้ำ
- ปิดรับก่อนเวลาได้ และกด "เริ่มรอบใหม่" ได้ทันทีหลังปิด
- ควบคุมได้เฉพาะรอบที่ตนเองเปิด (ดู [สิทธิ์การใช้งาน](#5-สิทธิ์การใช้งาน))
- ถ้าสลับแอปแล้วกลับมา หรือเน็ตกลับมา หน้าจะรีเฟรช QR และรายชื่อทันที

### ผู้ดูแลระบบ

- **แดชบอร์ด** ทักทายตามช่วงเวลา มีนาฬิกา แถบแจ้ง "ขณะนี้กำลังเปิดเช็กชื่ออยู่" (ทุกรอบของทุกอาจารย์) ตารางสอนวันนี้ที่ไฮไลต์คาบปัจจุบันพร้อมปุ่ม "เช็กชื่อ ›" สรุปการเข้าเรียน 30 วันล่าสุด แยกตามห้อง (คลิกแถวเพื่อไปดูรายงานห้องนั้น) และรายชื่อนักเรียนที่ควรติดตาม (คลิกเพื่อดูประวัติรายบุคคล)
- **ตารางสอน** จันทร์–ศุกร์ 8 คาบ คลิกช่องเพื่อเพิ่ม/แก้ไข/ลบ รองรับการสอนต่อเนื่องหลายคาบ มีมุมมองรายวันบนมือถือ
- **รายชื่อนักเรียน** เพิ่ม/แก้ไข/ลบ ค้นหาด้วยเลขที่ ชื่อ อีเมล หรือหมายเหตุ เพิ่มห้องใหม่ได้ขณะเพิ่มนักเรียน
- **หมายเหตุนักเรียน** ข้อความส่วนตัวที่เห็นเฉพาะแอดมิน (สูงสุด 500 ตัวอักษร) แสดงไอคอน 📝 ในรายการและหน้าประวัติ
- **รายงานผล** กรองตามห้องและช่วงวันที่ ดูภาพรวมแบบกราฟวงกลม แนวโน้มรายคาบ/รายวัน สมุดเช็กชื่อรายบุคคล และปฏิทินรายวัน/คาบ
- **ปรับสถานะ** มาเรียน / มาสาย / ลา / ขาด พร้อมหมายเหตุ รายคนหรือเช็กให้ทั้งคาบ และคืนค่ากลับตามระบบได้
- **ดาวน์โหลด Excel (.xlsx)** พร้อมสูตรสรุป การจัดรูปแบบ และตั้งค่าพิมพ์แนวนอน
- **ยกเลิกรอบ (void)** กรณีเปิดผิดหรือทดสอบ

## 2. สถาปัตยกรรมและไฟล์

ใช้ Apps Script **2 โปรเจ็กต์แยกกัน**

| โปรเจ็กต์  | หน้าที่                                                                    | ไฟล์                                                                                               |
| ---------- | -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| **Main**   | แสดงหน้าเว็บ ตรวจสิทธิ์ และอ่าน/เขียน Google Sheets                        | `Code.gs`, `Auth.gs`, `Home.html`, `Teacher.html`, `Student.html`, `Admin.html`, `appsscript.json` |
| **Bridge** | อ่านอีเมล Google ของผู้เข้าชม ออกตั๋ว (ticket) ลงลายเซ็น แล้วส่งต่อไป Main | `Code.gs` (ของ Bridge), `appsscript.json` (ของ Bridge)                                             |

> `Code.gs` และ `appsscript.json` ของ Main กับ Bridge เป็นคนละไฟล์ที่ชื่อซ้ำกัน ต้องวางคนละโปรเจ็กต์ อย่าสลับกัน

| ไฟล์ใน Main    | หน้าที่                                                                                       |
| -------------- | --------------------------------------------------------------------------------------------- |
| `Code.gs`      | ตรรกะหลักทั้งหมด: ตั้งค่าเริ่มต้น โทเค็น รอบเช็กชื่อ ฝั่งอาจารย์/นักเรียน รายงาน ตารางสอน รายชื่อ |
| `Auth.gs`      | ตรวจตั๋ว, whitelist ของฟังก์ชัน API (`api()`), ตัวช่วยเปลี่ยนเส้นทาง, `BRIDGE_URL`             |
| `Home.html`    | หน้าแรก เมนูตามสิทธิ์                                                                         |
| `Teacher.html` | หน้าอาจารย์: เปิดรอบ แสดง QR จัดการรายชื่อในรอบ                                               |
| `Student.html` | หน้านักเรียนหลังสแกน QR                                                                       |
| `Admin.html`   | หน้าผู้ดูแล: แดชบอร์ด ตารางสอน รายชื่อ รายงาน                                                 |

**เหตุผลที่แยก:** การอ่านอีเมลผู้ใช้ต้อง Deploy แบบ _User accessing the web app_ ส่วนการเข้าถึงชีตของเจ้าของระบบต้อง Deploy แบบ _Me_ จึงแยกเป็นสองแอป

```text
ผู้ใช้ ──► Bridge (อ่านอีเมล + สร้างตั๋ว HMAC-SHA256)
              │
              ▼
          Main (ตรวจตั๋ว + ตรวจสิทธิ์)
              ├─ นักเรียน : หน้าเช็กชื่อ
              ├─ อาจารย์  : เปิดรอบ + แสดง QR
              └─ แอดมิน   : แดชบอร์ด / รายงาน / จัดการข้อมูล
              │
              ▼
          Google Sheets
```

URL ที่อยู่ใน QR คือลิงก์ของ **Bridge** (`BRIDGE_URL?p=c&s=<รหัสรอบ>&t=<โทเค็น>`) เมื่อนักเรียนสแกน Bridge จะอ่านอีเมลของบัญชีที่ล็อกอิน ออกตั๋วอายุ 10 นาที แล้วส่งต่อไปหน้านักเรียนของ Main

### ตั๋วยืนยันตัวตน

- รูปแบบ `base64(email|เวลาหมดอายุ).ลายเซ็น` ลงลายเซ็นด้วย `AUTH_SECRET`
- หน้าเช็กชื่อนักเรียน (`p=c`) อายุ **10 นาที** หน้าอื่นอายุ **8 ชั่วโมง**
- ตั๋วอยู่ใน URL (`auth=`) ถือเป็นข้อมูลอ่อนไหว อย่าส่งต่อหรือโพสต์สาธารณะ
- เปิด Main โดยไม่มีตั๋วหรือตั๋วหมดอายุ ระบบจะส่งกลับไปยืนยันที่ Bridge ให้เอง
- ทุกการเรียกจากหน้าเว็บผ่าน `api()` ใน `Auth.gs` ซึ่งตรวจตั๋วและเรียกได้เฉพาะฟังก์ชันใน whitelist

### พารามิเตอร์หน้าเว็บ (`?p=`)

| ค่า       | หน้า                                                 |
| --------- | ---------------------------------------------------- |
| (ไม่ระบุ) | หน้าแรก เมนูตามสิทธิ์ (เช็กชื่อนักเรียน / สรุปผล)    |
| `t`       | อาจารย์: เปิดรอบและแสดง QR                           |
| `admin`   | ผู้ดูแลระบบ                                          |
| `c`       | นักเรียน: เช็กชื่อ (ใช้ `s` = รหัสรอบ, `t` = โทเค็น) |
| `ok`      | ให้นักเรียนเปิดครั้งแรกเพื่อกดอนุญาตบัญชีล่วงหน้า    |

**แจกลิงก์ของ Bridge เป็นจุดเริ่มต้นเสมอ**

## 3. ติดตั้งและตั้งค่า

### สิ่งที่ต้องเตรียม

1. บัญชี Google ของเจ้าของระบบ (เป็นเจ้าของทั้ง Sheets และ Apps Script ทั้งสองโปรเจ็กต์)
2. Google Sheets ว่าง 1 ไฟล์
3. อีเมล Google ของนักเรียน อาจารย์ และผู้ดูแล
4. แนะนำ Chrome เวอร์ชันล่าสุดทั้งบนคอมพิวเตอร์และโทรศัพท์

### A. สร้าง Main

1. สร้าง Google Sheets ใหม่ แล้วเปิด **ส่วนขยาย → Apps Script**
2. วาง `Code.gs` และสร้างไฟล์สคริปต์ชื่อ `Auth` วาง `Auth.gs`
3. สร้างไฟล์ HTML ชื่อ `Home`, `Teacher`, `Student`, `Admin` แล้ววางโค้ดตามชื่อ
4. เปิดไฟล์ manifest (**Project Settings → Show "appsscript.json"**) ตั้ง `timeZone` เป็น `Asia/Bangkok` และ `webapp.executeAs` เป็น `USER_DEPLOYING` (อย่าคัดลอก manifest ของ Bridge มาใช้)
5. รันฟังก์ชัน `setup` (กดอนุญาตสิทธิ์) เพื่อสร้างชีตทั้งหมด บันทึก `SS_ID` ตั้งรูปแบบคอลัมน์ข้อความ ซ่อนคอลัมน์ `secret` และเพิ่มบัญชีของคุณเป็นอาจารย์/แอดมินเริ่มต้น (ถ้าอ่านอีเมลไม่ได้ให้เพิ่มเองในชีต `Teachers` และ `Admins`)
6. รันฟังก์ชัน `createAuthSecret` แล้วคัดลอกค่า `AUTH_SECRET` จาก Execution log
7. **Deploy → New deployment → Web app** ตั้ง Execute as = **Me** และ Who has access ให้ผู้ใช้ทุกกลุ่มเข้าถึงได้ (เช่น Anyone with Google account) แล้วคัดลอก URL `/exec` เก็บเป็น `MAIN_URL`

### B. สร้าง Bridge

1. สร้างโปรเจ็กต์ Apps Script ใหม่ แยกจาก Main
2. วางโค้ด Bridge ลงใน `Code.gs`
3. ตั้ง `appsscript.json` ของ Bridge ให้เป็น

   ```json
   {
     "timeZone": "Asia/Bangkok",
     "runtimeVersion": "V8",
     "exceptionLogging": "STACKDRIVER",
     "oauthScopes": ["https://www.googleapis.com/auth/userinfo.email"],
     "webapp": { "executeAs": "USER_ACCESSING", "access": "ANYONE" }
   }
   ```

4. **Project Settings → Script Properties** เพิ่ม `AUTH_SECRET` = ค่าจากข้อ A.6 (ต้องตรงกันทุกตัวอักษร)
5. Deploy เป็น Web app แบบ **User accessing the web app** แล้วคัดลอก URL `/exec` เก็บเป็น `BRIDGE_URL`

### C. เชื่อมสองโปรเจ็กต์

| โปรเจ็กต์ | ไฟล์      | ตัวแปร                        |
| --------- | --------- | ----------------------------- |
| Main      | `Auth.gs` | `BRIDGE_URL` = URL ของ Bridge |
| Bridge    | `Code.gs` | `MAIN_URL` = URL ของ Main     |

จากนั้น Deploy ทั้งสองโปรเจ็กต์เป็น **New version** (Deploy → Manage deployments → Edit → New version) การบันทึกไฟล์อย่างเดียวไม่ทำให้เว็บแอปที่ Deploy อยู่เปลี่ยนตาม

### D. เตรียมผู้ใช้และทดสอบ

1. ใส่รายชื่อใน `Students`, `Teachers`, `Admins` (หรือเพิ่มนักเรียนผ่านหน้า Admin) แล้วรัน `clearCache` ถ้าแก้ชีตโดยตรง
2. ให้นักเรียนเปิด `BRIDGE_URL?p=ok` หนึ่งครั้ง เพื่อกดอนุญาตบัญชี
3. ทดสอบเป็นอาจารย์ (เปิดรอบ ดู QR) นักเรียน (สแกน) และแอดมิน (รายงาน, Excel)
4. ทดสอบกับจำนวนผู้ใช้ใกล้เคียงการใช้งานจริงก่อนเริ่มใช้

### E. อัปเดตระบบที่ติดตั้งไว้แล้ว

1. แก้ไฟล์ใน Main (และ Bridge ถ้ามีการแก้)
2. ถ้าแก้ `setup()` หรือ `HEADERS` ให้รัน `setup` อีกครั้ง (ไม่แตะข้อมูลเดิม)
3. Deploy เป็น **New version** ที่ deployment เดิม เพื่อให้ `MAIN_URL` และ `BRIDGE_URL` ไม่เปลี่ยน
4. ล้างแคชเบราว์เซอร์ (Ctrl+F5) แล้วทดสอบด้วยบัญชีอาจารย์ที่ไม่ใช่แอดมิน และบัญชีแอดมิน อย่างน้อยอย่างละ 1 บัญชี

## 4. โครงสร้าง Google Sheets

`setup()` สร้างชีตและหัวคอลัมน์ให้ (ชีตเดิมจะเติมเฉพาะหัวที่ขาด ไม่แตะข้อมูล)

| ชีต            | คอลัมน์                                                                       | หน้าที่                                                                                |
| -------------- | ----------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `Students`     | `email, studentId, name, class`                                               | รายชื่อนักเรียน (ทุกคอลัมน์เป็นข้อความล้วน)                                            |
| `Teachers`     | `email, name, fullName`                                                       | อีเมลที่มีสิทธิ์อาจารย์                                                                |
| `Admins`       | `email, name, fullName`                                                       | อีเมลที่มีสิทธิ์แอดมิน                                                                 |
| `Sessions`     | `sessionId, class, teacher, start, end, secret, status`                       | รอบเช็กชื่อ (`status` = `open` / `closed` / `void`) คอลัมน์ `secret` ถูกซ่อนไว้        |
| `Attendance`   | `timestamp, sessionId, class, email, studentId, name, deviceId, method, flag` | บันทึกการเช็ก (`method` = `qr` / `manual`, `flag` = `DEVICE_SHARED` เมื่อพบอุปกรณ์ซ้ำ) |
| `Adjustments`  | `sessionId, email, status, note, by, updatedAt`                               | การปรับสถานะโดยแอดมิน                                                                  |
| `Schedule`     | `entryId, teacher, day, period, class, subject, room, updatedAt`              | ตารางสอน (`day` 1–5 = จันทร์–ศุกร์) หนึ่งแถวต่อหนึ่งคาบ                                |
| `StudentNotes` | `email, note, updatedAt`                                                      | หมายเหตุนักเรียน (สร้างอัตโนมัติเมื่อใช้ครั้งแรก)                                      |

**หมายเหตุ**

- ระบบแสดงชื่อในคำทักทายจากคอลัมน์ `fullName` ของ `Teachers`/`Admins` เท่านั้น หากเว้นว่างจะใช้ส่วนหน้า `@` ของอีเมลแทน คอลัมน์ `name` ไม่ได้ถูกนำไปแสดงผล
- คอลัมน์ `studentId` ในชีต `Attendance` (คอลัมน์ E) ถูกตั้งเป็นข้อความล้วนโดย `setup()` เพื่อรักษาเลขศูนย์นำหน้า แถวที่บันทึกไว้ก่อนรัน `setup()` รอบนี้อาจสูญเสียเลขศูนย์ไปแล้ว
- `Sessions` เก็บ secret ของ QR และ Script Properties เก็บ `AUTH_SECRET` อย่าแชร์ Spreadsheet หรือสิทธิ์แก้ Apps Script ให้นักเรียน

## 5. สิทธิ์การใช้งาน

| กลุ่ม       | แหล่งสิทธิ์ | ทำอะไรได้                                                                    |
| ----------- | ----------- | ---------------------------------------------------------------------------- |
| นักเรียน    | `Students`  | เช็กชื่อในรอบของห้องตัวเอง                                                   |
| อาจารย์     | `Teachers`  | เปิด/ปิดรอบ ดู QR ติ๊กให้ ยกเลิกการเช็ก **เฉพาะรอบที่ตนเองเปิด**             |
| ผู้ดูแลระบบ | `Admins`    | แดชบอร์ด ตารางสอน รายชื่อ รายงาน ปรับสถานะ เช็กให้ทั้งคาบ void              |

- หน้าแรกแสดงเมนูที่ไม่มีสิทธิ์เป็นสีจางพร้อมป้าย "เฉพาะอาจารย์ / เฉพาะผู้ดูแลระบบ" และถ้าไม่มีสิทธิ์ใดเลยจะมีข้อความแจ้งให้ติดต่อผู้ดูแล
- การซ่อนเมนูไม่ใช่มาตรการความปลอดภัย ทุกฟังก์ชันฝั่งเซิร์ฟเวอร์ตรวจสิทธิ์ซ้ำ (`requireTeacher_`, `requireAdmin_`)
- แอดมินที่ต้องการเปิดรอบเช็กชื่อด้วย ต้องอยู่ในชีต `Teachers` ด้วย
- **การตรวจเจ้าของรอบ** (`assertOwner_`): การดู QR ดูสถานะ ปิดรอบ ติ๊กให้ และยกเลิกการเช็ก ทำได้เฉพาะอาจารย์ที่เปิดรอบนั้น หากควบคุมรอบของท่านอื่นจะขึ้น "รอบเช็กชื่อนี้เป็นของอาจารย์ท่านอื่น" ยกเว้นบัญชีที่อยู่ในชีต `Admins` (และอยู่ใน `Teachers` ด้วย) ซึ่งควบคุมได้ทุกรอบ เช่น ปิดรอบที่อาจารย์ลืมปิด
- ห้องหนึ่งมีรอบเปิดได้ทีละรอบเดียว หากอาจารย์ท่านอื่นพยายามเปิดห้องที่มีรอบค้างอยู่ จะถูกปฏิเสธ

## 6. วิธีใช้งาน

### อาจารย์

1. เปิดลิงก์ Bridge → เลือก **เช็กชื่อนักเรียน** (หรือกดปุ่ม "เช็กชื่อ ›" ที่คาบปัจจุบันบนแดชบอร์ด)
2. เลือกห้องและเวลา → **เริ่มเช็กชื่อ** แล้วแสดง QR บนโปรเจกเตอร์
3. นักเรียนสแกน รายชื่อสองฝั่งอัปเดตให้อัตโนมัติ
4. ใช้ **ติ๊กให้** / **ยกเลิก** เมื่อจำเป็น และ **ปิดรับเช็กชื่อ** เมื่อเสร็จ (มีกล่องยืนยัน)
5. หลังปิดรอบจะเห็นสรุปจำนวนผู้เช็ก/ยังไม่เช็ก และยังแก้รายชื่อได้ กด **เริ่มรอบใหม่** เพื่อรีเฟรชหน้าเปิดรอบถัดไป
6. ใช้บัญชี Google เดียวกันตลอดการเช็กชื่อ หากสลับบัญชีกลางคันจะขึ้นว่ารอบเป็นของอาจารย์ท่านอื่น

### นักเรียน

1. ล็อกอินบัญชี Google ที่ลงทะเบียนไว้ (ใช้ Chrome โปรไฟล์ที่ถูกบัญชี)
2. สแกน QR ด้วยกล้องโทรศัพท์
3. รอผล ✓ เช็กชื่อสำเร็จ หาก QR หมดอายุให้สแกน QR ที่แสดงอยู่ปัจจุบันใหม่ (ภาพที่ถ่ายหรือส่งต่อใช้ไม่ได้นานเกิน 20–30 วินาที)

### ผู้ดูแลระบบ

**แดชบอร์ด**

- แถบสีเขียว "ขณะนี้กำลังเปิดเช็กชื่ออยู่" แสดงห้องและช่วงเวลาของทุกรอบที่ยังเปิด
- ตารางสอนวันนี้ใช้เวลาเครื่องของผู้ใช้ตัดสินว่าคาบไหนคือ "ขณะนี้" วันเสาร์–อาทิตย์จะแสดงข้อความวันหยุด
- สรุป 30 วันล่าสุดมีอัตราเข้าเรียนรวม จำนวนคาบ มาสาย ขาด และแถบสัดส่วนสี่สถานะ ปุ่ม "รีเฟรช" โหลดใหม่พร้อมหน้าจอโหลด
- "นักเรียนที่ควรติดตาม" คือนักเรียนที่มีข้อมูลอย่างน้อย 3 คาบ และอัตราต่ำกว่า 80% (แสดงอัตราต่ำสุด 8 คนแรก)

**ตารางสอน**

- ผูกกับอีเมลของแอดมินที่บันทึก ใช้แสดงในแดชบอร์ดและใช้จับคู่ชื่อวิชา/คาบ/สถานที่ในรายงาน
- การจับคู่ใช้ อีเมลอาจารย์ที่เปิดรอบ + วัน + คาบ (รอบที่เปิดก่อนคาบไม่เกิน 15 นาทีนับเป็นคาบนั้น) จึงควรให้เจ้าของตารางสอนเป็นคนเปิดรอบเอง
- ตารางสอนไม่ได้เปิดรอบเช็กชื่ออัตโนมัติ
- หน้าต่างแก้ไขมีช่อง วิชา/กิจกรรม ห้องเรียน (เลือกจากรายการหรือพิมพ์เอง) สถานที่สอน และ "สอนต่อเนื่องถึง" ช่องเดิมในช่วงที่เลือกจะถูกแทนที่
- ระบบบันทึกทีละคาบในชีต `Schedule` ส่วนหน้าตารางจะรวมคาบที่ติดกันและข้อมูลเหมือนกันเป็นช่องเดียว **แต่ไม่รวมข้ามช่วงพัก** เช่น คาบ 2–3 แสดงเป็นสองช่องคั่นด้วยพัก 10 นาที
- เมื่อเปิดช่องที่เป็นบล็อกต่อเนื่อง ช่อง "สอนต่อเนื่องถึง" จะเลือกปลายบล็อกให้ และปุ่ม **ลบคาบนี้** ลบทั้งบล็อก
- บนมือถือตารางแสดงทีละวัน เริ่มที่วันปัจจุบัน

**รายชื่อนักเรียน**

- อีเมลต้องไม่ซ้ำทั้งระบบ เลขที่ต้องไม่ซ้ำภายในห้องเดียวกัน
- เลขที่เก็บเป็นข้อความ (รักษาเลขศูนย์นำหน้า) และเรียงเชิงตัวเลข (2 ก่อน 10)
- คลิกแถวเพื่อแก้ไข/ลบ/แก้หมายเหตุ ผลสำเร็จแสดงเป็นข้อความแจ้งมุมขวาล่าง
- **แก้อีเมลผ่านหน้า Admin** ระบบจะย้ายประวัติใน `Attendance` และ `Adjustments` และหมายเหตุตามให้ แต่ถ้าแก้ในชีตโดยตรงจะไม่ย้าย ทำให้ประวัติหายและถูกนับเป็นขาด
- **ลบนักเรียน** ลบแถวใน `Students` และหมายเหตุ แต่ประวัติใน `Attendance` และ `Adjustments` ยังอยู่

**รายงานผล**

- เมื่อเปิดหน้านี้ครั้งแรกจะโหลดย้อนหลัง 30 วัน เปลี่ยนห้องในรายการแล้วโหลดใหม่ทันที หรือใช้ปุ่มค้นหาด่วน วันนี้ / 7 วัน / 30 วัน / ทั้งหมด หรือกำหนดช่วงวันที่เอง แล้วกด "ค้นหา" ปุ่ม "ล้างค่าตัวกรอง" กลับไปห้องแรกและช่วง "ทั้งหมด"
- การ์ดภาพรวมแสดงกราฟวงกลมสัดส่วน มา/สาย/ลา/ขาด กราฟแนวโน้มเลือกมุมมองรายคาบหรือรายวันได้
- **คลิกแท่งกราฟ** เพื่อดูสรุปของวัน/คาบนั้น ปิดสรุปได้ 3 วิธี: ปุ่ม **✕ ปิด**, คลิกแท่งที่เลือกอยู่ซ้ำ, หรือกด **Esc**
- แท็บ _แยกรายบุคคล_ เป็นสมุดเช็กชื่อ จัดกลุ่มเดือน → วัน → คาบ ตรึงคอลัมน์ซ้าย/ขวา เรียงตามเลขที่ / % เข้าเรียน / จำนวนขาด
- แท็บ _แยกแต่ละวัน/คาบ_ เป็นปฏิทินแยกเดือน โหมดรายคาบแสดงทีละคาบพร้อมชื่อวิชา โหมดรายวันรวมทุกคาบของวัน สีชิป: แดง = ต่ำกว่า 80%, เหลือง = มีคนสายหรือขาด, เขียว = ไม่มีสายและไม่มีขาด
- คลิกชิปเพื่อเปิดรายชื่อทั้งคาบ แก้สถานะและหมายเหตุรายคนได้ทันทีเมื่อเปลี่ยนค่า แถวที่แอดมินปรับแล้วมีป้าย "✎ ผู้ดูแลปรับแก้" และปุ่ม "คืนค่า" คอลัมน์ "การเช็กชื่อ" แสดงเวลาสแกนเฉพาะคนที่สถานะเป็นมาเรียน (หรือ "อาจารย์ติ๊กให้")
- คลิกชื่อนักเรียนเพื่อดูประวัติ: กราฟวงกลม จำนวนแต่ละสถานะ คาบทั้งหมด ขาดติดต่อกันสูงสุด จำนวนคาบที่ปรับแก้ ป้ายเตือนเมื่อต่ำกว่าเกณฑ์ หมายเหตุ และปฏิทินล่าสุดก่อน คลิกที่คาบเพื่อแก้เฉพาะคาบนั้น (แสดงวิชา คาบ เวลา วิธีเช็ก)

**เช็กให้ทั้งคาบและยกเลิกรอบ**

- _เช็กชื่อให้นักเรียนทุกคนในคาบเรียนนี้_ : คนที่ไม่มีบันทึกสแกนจะถูกตั้งเป็น "มาเรียน" (บันทึกเป็นการปรับแก้) ส่วนคนที่สแกนแล้วจะ **ลบการปรับแก้เดิมทิ้ง** (เช่น ที่เคยตั้งเป็นสาย/ลา) เพื่อกลับเป็นมาเรียนตามเวลาสแกนเดิม
- _ตั้งค่าให้ไม่นับคาบนี้_ (void) ไม่ลบข้อมูล แต่ตัดรอบออกจากรายงานและแดชบอร์ด และกู้คืนจากหน้าเว็บไม่ได้ (ต้องแก้คอลัมน์ `status` ในชีต `Sessions` เอง)

**ดาวน์โหลด Excel**

- สร้างฝั่งเบราว์เซอร์ด้วย ExcelJS 4.4.0 ที่โหลดจาก CDN (jsdelivr) จึงต้องมีอินเทอร์เน็ต ชื่อไฟล์ `attendance_<ห้อง>.xlsx`
- ตรงกับตารางรายบุคคลที่เห็นบนจอ รวมลำดับการเรียงที่เลือก มีสูตร `COUNTA`/`COUNTIF` สรุปผล ตรึงหัวตาราง ตั้งพิมพ์แนวนอนพอดีหนึ่งหน้ากว้าง และเน้นสีแดงเมื่ออัตราต่ำกว่าเกณฑ์

## 7. หลักการคำนวณสถานะ

| รหัส | ความหมาย | สัญลักษณ์ |
| ---- | -------- | --------- |
| `p`  | มาเรียน  | `/`       |
| `l`  | มาสาย    | `ส`       |
| `v`  | ลา       | `ล`       |
| `a`  | ขาด      | `ข`       |

ลำดับการตัดสิน:

1. มีการปรับโดยแอดมิน (`Adjustments`) → ใช้สถานะนั้น
2. ไม่มีการปรับ แต่มีบันทึกใน `Attendance` (สแกนหรืออาจารย์ติ๊ก) → **มาเรียน**
3. ไม่มีทั้งสอง → **ขาด**

หมายเหตุ:

- ระบบอัตโนมัติแยกได้แค่ มา/ขาด ส่วน **สาย และ ลา ต้องให้แอดมินปรับเอง**
- อัตราเข้าเรียน = (มา + สาย) ÷ ทั้งหมด การลาไม่นับเป็นเข้าเรียน
- ต่ำกว่า **80%** แสดงสีแดง
- รายงานนับเฉพาะรอบที่ปิดแล้วหรือหมดเวลาแล้ว ไม่รวมรอบที่ยังเปิดอยู่และรอบ `void`
- รายชื่อที่ใช้คำนวณคือนักเรียนใน `Students` ปัจจุบันของห้องนั้น นักเรียนที่ถูกลบจะไม่ปรากฏในรายงาน และนักเรียนที่เพิ่มภายหลังจะถูกนับเป็นขาดในรอบเก่าด้วย

## 11. การสำรองและดูแลข้อมูล

1. สำรอง Spreadsheet ด้วย **File → Make a copy** ก่อนแก้ข้อมูลจำนวนมากหรือปรับโครงสร้าง
2. จำกัดสิทธิ์เข้าถึง Spreadsheet และ Apps Script เฉพาะผู้ดูแล
3. อย่าลบ/เปลี่ยนชื่อหัวคอลัมน์ในชีตระบบ เพราะโค้ดอ่านตามตำแหน่งและชื่อ
4. ใช้ `Attendance`, `Sessions`, `Adjustments` ตรวจสอบประวัติย้อนหลัง
5. เก็บ `AUTH_SECRET` ใน Script Properties เท่านั้น ห้ามใส่ในโค้ด README หรือ repository สาธารณะ
6. หากสงสัยว่า `AUTH_SECRET` รั่ว ให้รัน `createAuthSecret` ใน Main แล้วนำค่าใหม่ไปแทนที่ใน Script Properties ของ Bridge จากนั้น Deploy ใหม่ทั้งสองโปรเจ็กต์
7. `clearCache` ล้างแคช `students`, `teachers`, `admins` เท่านั้น แคชของรอบ (`sess_*`) และบันทึกเช็กชื่อ (`att_*`) หมดอายุเองใน 6 ชั่วโมง หน้ารายงานอ่านชีตโดยตรงจึงเห็นการแก้ในชีตทันที แต่หน้าอาจารย์ที่กำลังเปิดรอบและการปรับสถานะอาจยังใช้ค่าจากแคชของรอบนั้น
8. ชีต `Attendance` โตขึ้นตามจำนวนการเช็กชื่อ และรายงาน/แดชบอร์ดอ่านทั้งชีตทุกครั้ง เมื่อจบภาคเรียนควรทำสำเนาเก็บถาวรและเริ่มภาคเรียนใหม่ในไฟล์ใหม่ เพื่อไม่ให้ระบบช้าลง

## 12. ข้อจำกัด

- **กันการเช็กแทนได้ไม่ 100%** หากนักเรียนที่อยู่ในห้องล็อกอินบัญชีเพื่อนบนเครื่องตนเองแล้วสแกน ระบบอาจตรวจไม่พบ แฟลกอุปกรณ์ซ้ำเป็นเพียงสัญญาณ ไม่ใช่หลักฐานยืนยันตัวบุคคล และหากล้างข้อมูลเบราว์เซอร์ `deviceId` จะเปลี่ยน
- **โควตา Apps Script** คำขอทั้งหมดใช้โควตาของเจ้าของระบบ หากสแกนพร้อมกันจำนวนมาก (เช่น 40 คนพร้อมกัน) อาจช้า หน้านักเรียนจะลองใหม่ให้เองสูงสุด 2 ครั้ง (เฉพาะกรณีติดคิวหรือหมดเวลา) ถ้ายังไม่สำเร็จต้องสแกนใหม่ ควรทดสอบก่อนใช้จริง
- **ขนาดแคช** CacheService เก็บได้ราว 100KB ต่อคีย์ ถ้ารายชื่อนักเรียนทั้งระบบมากจนเกินขนาดนี้ ระบบจะข้ามแคชและอ่านชีตทุกครั้ง ทำให้ช้าลง
- **ตั๋วนักเรียนอายุ 10 นาที** เปิดหน้าค้างนานต้องสแกนใหม่
- **ตั๋วแอดมิน/อาจารย์อายุ 8 ชั่วโมง** และอยู่ใน URL ผู้ที่ได้ลิงก์ที่มี `auth=` จะใช้งานแทนได้จนกว่าตั๋วหมดอายุ อย่าแชร์หน้าจอหรือลิงก์นั้น
- **ล็อกอินหลายบัญชี Google** ในเบราว์เซอร์เดียวอาจเลือกผิดบัญชี
- **ไม่แยกมาสายอัตโนมัติ** การสแกนทุกกรณีนับเป็นมาเรียน
- **ตารางสอนเป็นข้อมูลประกอบ** ไม่ได้ควบคุมการเปิดรอบ และผูกกับอีเมลของแอดมินแต่ละคน
- **รายชื่อในรายงานเป็นรายชื่อปัจจุบัน** นักเรียนที่เพิ่มกลางภาคจะถูกนับเป็นขาดในรอบก่อนหน้า
- **เวลาบนหน้าแอดมินใช้นาฬิกาเครื่องผู้ใช้** (คาบปัจจุบัน ปุ่มค้นหาด่วน "วันนี้/7 วัน/30 วัน") ส่วนเซิร์ฟเวอร์ใช้ `Asia/Bangkok` หากเครื่องตั้งเขตเวลาต่างกัน ผลอาจคลาดเคลื่อน
- **Excel ต้องใช้อินเทอร์เน็ต** เพราะโหลด ExcelJS จาก CDN
- **ฟอนต์ Noto Sans Thai และไลบรารี QR** โหลดจาก CDN (Google Fonts, cdnjs) หน้าอาจารย์ต้องเข้าถึง cdnjs ได้เพื่อสร้าง QR
- **ข้อมูลส่วนบุคคล** ระบบเก็บอีเมล เวลาเช็กชื่อ และรหัสอุปกรณ์ ควรแจ้งผู้เรียน/ผู้ปกครองและปฏิบัติตามนโยบายคุ้มครองข้อมูลของสถานศึกษา

## 14. หมายเหตุสำหรับผู้พัฒนา

- ห้ามเปิดเผย `AUTH_SECRET` หรือ URL ที่มี `auth=`
- เพิ่ม/เปลี่ยนฟังก์ชันที่หน้าเว็บเรียก ต้องเพิ่มใน whitelist `FN` ของ `api()` (`Auth.gs`) และเรียก `requireTeacher_()`/`requireAdmin_()` ภายในฟังก์ชันนั้น
- ฟังก์ชันฝั่งอาจารย์ที่รับ `sessionId` ต้องเรียก `assertOwner_(session, email)` หลังโหลดรอบ โดยเก็บค่า `email` จาก `requireTeacher_()` ไว้ก่อน (ระวังชื่อซ้ำกับพารามิเตอร์ `email` ของนักเรียน เช่นใน `markManual`/`removeAttendance` ใช้ชื่อ `me`)
- ฟังก์ชันฝั่งแอดมินที่รับ `sessionId` (`setStatus`, `markAllPresent`, `voidSession`) ตรวจแค่สิทธิ์แอดมิน ไม่ตรวจเจ้าของรอบ
- ก่อนเปลี่ยนชื่อชีตหรือหัวคอลัมน์ ตรวจ `SHEETS` และ `HEADERS` ใน `Code.gs` ทุกจุดที่อ้างถึง `rows_()` อ่านตามลำดับคอลัมน์ใน `HEADERS`
- ข้อมูลที่ส่งจาก `getReport` ใช้สตริงยาวเท่าจำนวนนักเรียน (`st` = สถานะ, `ad` = 1 ถ้าแอดมินปรับ) ฝั่ง `Admin.html` อ้างตำแหน่งตามลำดับนักเรียน (`IDX`) จึงต้องไม่สลับลำดับรายชื่อระหว่างส่งข้อมูล
- ตารางสอนใน `Admin.html` (`renderSched`) รวมช่องโดยเทียบ **ตำแหน่งใน `PERIODS`** ไม่ใช่เลขคาบ จึงไม่รวมข้ามช่วงพัก และ `blockEnd` ใช้หลักเดียวกันหาปลายบล็อก หากเพิ่ม/ย้ายช่วงพักใน `PERIODS` ให้ตรวจพฤติกรรมนี้ด้วย
- ป้ายช่วงพักในตารางสอนใช้ `<span>` ภายใน `<td>` เพื่อหมุนข้อความแนวตั้ง (`writing-mode`) เพราะตั้ง `writing-mode` ที่ `<td>` โดยตรงอาจจัดข้อความไม่กึ่งกลางในบางเบราว์เซอร์
- การส่งออก Excel ทำฝั่งเบราว์เซอร์ทั้งหมด (`buildExcelBlob` ใน `Admin.html`) ไม่มีฟังก์ชันฝั่งเซิร์ฟเวอร์สำหรับสร้างไฟล์
- การปิดสรุปกราฟแนวโน้มอยู่ใน `closeTrendDetail()` ปุ่มปิดใช้ attribute `data-trend-close` แทน `data-a` เพื่อไม่ชนกับตัวจัดการคลิกหลัก ลำดับการปิดด้วย Esc คือ ป๊อปอัปตารางสอน → โมดัลเพิ่ม/แก้ไขนักเรียน → แผงรายงาน → สรุปกราฟ (ต้องตรวจ `$("trendDetail")` ว่าไม่เป็น `null` ก่อนเสมอ เพราะ element นี้มีเฉพาะหลังโหลดรายงาน)
- ตัวช่วยแจ้งเตือนใน `Admin.html`: `toast(msg, isErr)` สำหรับข้อความมุมขวาล่าง และ `setLoading(show, text)` สำหรับฉากโหลดเต็มจอ (นับซ้อนได้ ต้องเรียก `setLoading(false)` ให้ครบทุกครั้งที่เรียก `true`)
- ปุ่มบนหน้าแอดมินใช้รูปแบบ `data-a="ชื่อคำสั่ง"` ให้ตัวจัดการคลิกกลางใน `document` เป็นผู้เรียกฟังก์ชัน เมื่อเพิ่มคำสั่งใหม่ให้เพิ่มเงื่อนไขในตัวจัดการนั้น
- ข้อควรระวังเมื่อแก้ไฟล์ HTML ด้วยมือ: วงเล็บปีกกาขาดเพียงตัวเดียวทำให้สคริปต์ทั้งหน้าไม่ทำงาน (หน้า "ค้าง") ตรวจใน DevTools Console ก่อน Deploy
- ทดสอบทั้งสามบทบาท (นักเรียน อาจารย์ที่ไม่ใช่แอดมิน และแอดมิน) ก่อน Deploy ใช้งานจริง
